:::tip[In short]

- **What this covers:** the AI/ML Evaluation Framework repository, read from its README, its folder READMEs and its directory tree.
- **What it is:** an evaluation tool for AI/ML scenarios in media services. Its README names 3GPP TR 26.927 as its source. It is marked as under development.
- **What works today:** scripts for compressed model transmission for speech recognition, split inferencing for object detection, and a translation scenario with four trained models. Human pose estimation, hand gesture recognition and federated learning have no scripts yet.
- **Standards:** no 3GPP network function is implemented here, so there is no case-by-case audit against a specification.

:::

For the technology background, see [AI/ML Evaluation Framework on the Tech portal](/tech/ai-ml). For how to run the tool, see the [Tutorials](/testbeds/ai-ml/tutorials).

## What it is

The repository is an evaluation tool, not a service or a network function. Its README describes it as "the implementation of the AI/ML evaluation framework as defined in 3GPP SA4 TR26.927", used for the scenarios collected for the FS_AI4Media study. The framework documents common testbed architectures and anchors, metrics (AI/ML task metrics and feasibility or performance metrics), and the test configuration and constraints of each scenario.

## Scenarios

The README lists six scenario headings. The translation scenario is described in the README of its scripts folder.

- **Transmission of compressed AI/ML model data for automatic speech recognition.** A pre-trained model (wav2vec 2.0 or HuBERT) is compressed before it is sent to a device, to reduce bandwidth or latency. The README has a figure for it. The code is in the ASR scripts folder, under a compression framework with its own README. It runs a codec pipeline that encodes and decodes a model and reports its size and recognition performance before and after. It has a NNCodec-based coder and a dummy coder, a script that sweeps quantisation parameters with configuration files, a plotter for the results, and Docker and Apptainer helpers. The ASR folder's own README has only a title.
- **Split inferencing for human pose estimation.** The README describes splitting PoseNet at different layers and measuring the delivery of the split model and of the intermediate data between two nodes. The scripts folder for body pose holds a README with only a title and no scripts, so this scenario is planned.
- **Split inferencing for object detection and labeling.** A pre-trained model detects objects in a video sequence, and the model is split in two parts, one on the device and one in the network. The README has a figure for it. The scripts folder holds scripts to convert and split a RetinaNet model, run inference whole and split, run it with ONNX, visualise results and calculate mean average precision. The folder README has only a title.
- **IMS real-time translation.** The README of the translation scripts folder calls it the IMS-based real-time translation test scenario. The folder holds scripts to download Tatoeba sentence pairs, prepare dictionaries, train a Transformer translation model (also in a distributed variant) and translate sentences, plus scripts for split translation and a WebRTC translator that its README does not describe. The top-level README has no heading for this scenario.
- **Split inferencing for hand gesture recognition.** The heading has no text in the README. It is planned.
- **Video super resolution in video call.** The README gives the motivation (video call resolution of 480p today, higher for XR calls). The repository has no scripts for it, so it is planned.
- **Federated learning.** The heading has no text in the README. It is planned.

A scripts folder for object tracking also exists. It holds a README with only a title, and the top-level README has no heading for it.

## What is in the repository

- **README and licence:** the README carries the under-development status badge and the 5G-MAG Public License (v1.0).
- **Scripts:** one folder per scenario, as described above.
- **Models:** the translation models for English to German, German to English, English to French and French to English, and a RetinaNet model in PyTorch and ONNX formats. They are stored with Git LFS. The folder README points to the ONNX Model Zoo, PyTorch Hub and TensorFlow Hub for candidate models.
- **Datasets:** the folder holds only a README, which gives a download link for the SFU-HW-Objects dataset and its predictions. The datasets themselves are hosted outside the repository.
- **Docker:** a Dockerfile for a container image of the evaluation environment, with Ubuntu 22.04 and Nvidia GPU support.
- **Figures:** one for the speech recognition scenario and one for object detection.

## Relation to the standards

This project does not implement a 3GPP network function. It is an evaluation tool, so there is no case audit against a specification.

The standards are background to the tool, not requirements it implements:

- **TS 23.288:** the machine learning clauses of the network data analytics architecture set the context for AI/ML in the 5G system. The repository does not implement them.
- **TR 26.847 and TR 26.927:** informative technical reports of 3GPP SA4. TR 26.927 is the source named in the README. TR 26.847 holds the evaluation testbed architectures, anchors and feasibility evaluations for the scenarios.

For the standards themselves, see [AI/ML on the Standards portal](/standards/ai-ml).
