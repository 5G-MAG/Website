:::tip[In short]

- **What this covers:** the Beyond 2D Evaluation Framework repository, read from its README, its folder READMEs and its directory tree.
- **What it is:** scripts and configuration files for reproducible evaluation in the 3GPP SA4 Feasibility Study on Beyond 2D Video (FS_Beyond2D), which will result in TR 26.956.
- **What works today:** two frameworks, one for multi-view plus depth (MVD) built around the TMIV encoder and decoder, and one for V-PCC point clouds built around the MPEG V-PCC test model. The README lists three scenarios whose descriptions are still to be written.
- **Standards:** the 5G Media Streaming specifications explored here (TS 26.501, TS 26.512) fall on no component of this repository, so there is no case-by-case audit against them.

:::

For the technology background, see the [Technology page](/tech/beyond-2d). For how to run the tools, see the [Tutorials](/testbeds/beyond-2d/tutorials).

## What it is

The repository is an evaluation toolset, not a service or a player. Its README describes it as scripts and configuration files for reproducible evaluation in FS_Beyond2D. The study covers several Beyond 2D representations and service scenarios, and it is based on the SP-240479 study item description. Source sequences, bitstreams and rendered pose trace videos are not in the repository; the README says they are on separate servers, listed in the technical report.

The README states that the repository has two frameworks, each with its own instructions: the `mvd` folder and the `point_cloud` folder.

## Scenarios

The README lists three scenarios and says their descriptions are still to be written.

- **Scenario 1:** UE-to-UE stereoscopic video live streaming. The repository has no folder or script for it, so it is planned.
- **Scenario 2:** streaming of professionally produced volumetric video with a single asset containing people.
- **Scenario 3:** on-demand streaming of multi-view plus depth.

The README does not say which folder serves which scenario. The `mvd` folder is the multi-view plus depth framework, which matches the wording of Scenario 3; the `point_cloud` folder handles V-PCC content, which the README does not tie to a numbered scenario.

## Multi-view plus depth framework

The `mvd` folder runs a complete experiment as a graph of jobs.

- **How it runs:** a setup script builds the software; the README says it also installs Ubuntu packages when called with `--system`. A configuration script then writes a `build.ninja` file with the dependency graph of all jobs, and running `ninja` completes the experiment. A `--slurm` option runs each job as a batch job on a Slurm cluster, with a small helper script that waits for each job.
- **What it evaluates:** by default three content items (Bartender, Breakfast, DanceMoves), three coding conditions (A, FV, SCV), four rate points (RP1 to RP4) and input frame counts of 3 and 65. Each can be changed with a command-line option.
- **Configuration:** a folder of JSON files for each condition and for the TMIV encode, mux and decode steps, JSON files describing the three sequences (with checksum files for two of them), pose trace CSV files, and a CSV of fixed quantisation parameters for texture and geometry at each rate point.
- **Tools used:** the README says the framework builds TMIV 24.0 and QMIV 2.0 from source, together with the video codecs VVenC, VVdeC, HM and Kvazaar, among other libraries. The configuration script selects HM as the video encoder where it sets one.
- **Outputs:** intermediate and final MIV bitstreams, coded video sub-bitstreams, reconstructed source view and interpolated pose trace YUV files, objective metric files (`.qmiv`), and TMIV parser logs, log files and bitrate reports for analysis. A script to collect the objective results is included.
- **Requirements:** the README lists 32 GB of RAM, 1 TB of free disk space and Ubuntu 24.04.02 or later (WSL 2 on Windows), and advises limiting parallel jobs on a single machine because encoding and decoding are memory intensive.

## Point cloud framework

The `point_cloud` folder provides tools to generate, decode and analyse V-PCC content. Its README points to three documents in its `doc` folder, one for each stage.

- **PLY generation:** converts meshes into point cloud frames (PLY) for five content items (Mitch, JuggleSoccer, Henry, Nathalie, Aliyah). The documentation describes a sampling pass, a quantisation pass and a cleaning pass that removes duplicate points, aiming at about 2 million points per frame, with checksum files to verify the result.
- **PLY to bin:** encodes each sequence with the MPEG V-PCC test model (TMC2), decodes it, computes objective metrics with the MPEG mmetric software (PCC and PCQM metrics), and writes CSV files and Excel workbooks from a template. The test configuration JSON files define the profiles, frame counts and rates.
- **Bin to video:** decodes V-PCC bitstreams, or takes point clouds directly, and renders videos with the MPEG 3DG renderer, driven by JSON files for render jobs, camera paths and backgrounds.
- **Requirements:** the documents list Python 3.11 and CMake 3.26 or above (under 4.0). The tools download and build the test model and the other MPEG software themselves.
- **Contact and licence:** the folder README gives two InterDigital contacts for issues and carries its own licence notice, which refers to the 5G-MAG reference tools licence.

## What is in the repository

- **README and licence:** the README carries a status badge and the 5G-MAG Public License v1.0.
- **`mvd`:** the multi-view plus depth framework described above.
- **`point_cloud`:** the V-PCC framework described above, with its documentation, JSON configuration, sequence configuration files and checksum files.
- **Content:** none. Source sequences and bitstreams are hosted outside the repository.

## Relation to the standards

This project does not implement a 3GPP network function or a media streaming client or server. The 5G Media Streaming specifications explored here (TS 26.501 and TS 26.512) fall on no component of this repository, so there is no case audit against them.

The relevant references are the study and its report:

- **FS_Beyond2D and TR 26.956:** the README names the study (based on SP-240479) and says it will result in TR 26.956. The repository holds the scripts and configuration for evaluating the representations the study covers.

For the standards themselves, see [Beyond 2D Video Experiences: Specification list](/standards/beyond-2d).

## Used with other projects

- **MPEG V3C Immersive Platform:** a related project for volumetric encoding and rendering tools. The README does not mention it. See [Volumetric Video Experiences](/reference-tools/v3c).
