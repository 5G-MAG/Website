This page sets out what the VOPS Conformance Validator covers, as stated in its repository README.

:::tip[In short]

- **What the tool checks:** the bitstream requirements of the AVC, HEVC and MV-HEVC operation points of TS 26.265 V19.3.0 (formats, colour, frame packing, layers and levels). It does not decode, encode or check a receiver.
- **What is covered:** most checks exist, but several requirements are checked only partly or not at all: bit depth, frame rates, projection, the AVC 120 Mbps limit, the 4:2:0 and aspect-ratio checks for UHD, and AVC-HD has none of the representation-format checks that the HEVC HD operation point has. Some stereo checks do not make a failing stream fail.
- **Source of this page:** an audit of the `main` branch of the repository on 2026-10-21: every requirement split into the cases its clause defines, each case read against the XSD rules and the parser by one reader and then independently by a second, with a third reading where they disagreed. The H.264 and H.265 texts were not available, so codec-level values are taken as the rules give them.

:::


## What This Project Implements

The validator verifies that an input video bitstream conforms to a given operation point defined in 3GPP TS 26.265 (Media Delivery: Video Capabilities and Operation Points). It parses the bitstream into an XML description, checks that description against XSD 1.1 schemas, one set per operation point, and reports every passing and failing assertion.

TS 26.265 V19.3.0, clause B.2.3: "A conformance validator for testing bitstreams for conformance against the operation points defined in this specification is provided".

It is a conformance tool, not an implementation of the specification: it tests bitstreams produced by encoders, and does not encode or decode video.

### Operation points

The validator carries a rule set for each of the seven operation points of TS 26.265, under eight names (`3GPP-AVC-HD`, `3GPP-HEVC-HD`, `3GPP-HEVC-HDR`, `3GPP-HEVC-UHD`, `3GPP-HEVC-UHD-HDR`, `3GPP-HEVC-Stereo`, `3GPP-MV-HEVC-Main-Stereo` and `3GPP-MV-HEVC-Ext-Stereo`). The README states that "implemented" means the XSD schemas and the parser exist, and that validation against real bitstreams may reveal issues.

### Boundary with 3GPP

TS 26.265 V19.3.0, clause B.2.3: "The detailed semantics and the format of the report is for further study." The JSON report format is therefore this tool's own, not one the specification defines.
