:::tip[In short]

- **What exists:** there is no dedicated RTC Reference Tool yet. The only RTC-related code is `rt-3gpp-swap`, the SWAP reference implementation (a Node.js signalling server and a client library) held in the repository of the [Conversational Avatar Communication with MPEG ARF](/reference-tools/avatar) project, which owns it.
- **What SWAP is:** SWAP (Simple WebRTC Application Protocol) is the signalling protocol of TS 26.113 (clause 13.2.4) that lets two real-time communication endpoints set up a call through a signalling server. It runs on the RTC-4s reference point, between the RTC Client and the WebRTC Signalling Function of the RTC AS.
- **Which specification it follows:** TS 26.113 V19.2.0. Releases 18 to 20 are judged on the same text.
- **Source of this page:** an audit of the `main` branch of `rt-3gpp-swap` on 2026-10-21. The RTC AF, the Media Session Handler, the ICE function and the other RTC AS functions are not part of it.

:::

For what the specifications define, see the [Technology](/tech/rtc).

## What the SWAP code implements

- **Implemented:** the SWAP signalling over WebSocket at `/3gpp-swap/v1` with the `3gpp.SWAP.v1` subprotocol; connect, accept, reject, update, close and application messages; matching criteria and endpoint selection. Message integrity and payload encryption are available as options in the library; their use in the reference server is limited.
- **Needs fix:**
  - Errors are sent as a SWAP response whose description joins the Problem Details title and detail, not as a Problem Details object.
  - A message to an endpoint that never registered is acknowledged, not answered with an error.
  - On a received close the client does not send the accept itself.
  - The reference to the request in a reject is optional.
  - The server prefers the endpoint with the most matching criteria and picks at random only among ties.
- **Not implemented:** handling of the Service Access Information and `swapEndpoints`, processing criteria, checking the application message type, and a client that listens for point-to-point connections.
- **Not shown:** cases that depend on the WebSocket library's own behaviour, which is not part of the repository.
