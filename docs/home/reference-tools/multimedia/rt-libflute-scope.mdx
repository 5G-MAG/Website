**Category:** IETF Implementations

## What this page covers

An audit of what [rt-libflute](https://github.com/5G-MAG/rt-libflute) implements today, checked against the source code and the primary specification text (TS 26.346 V18.2.0, TS 26.517, RFC 3926/3450/3451/5052/3695/5053). See [rt-libflute Specifications](./rt-libflute-standards) for what each reference means and why FLUTE version 1 is the applicable profile.

:::note[Audit baseline]
This assessment was made against the `development` branch at commit `1199cce` (2026-08-11). Features carried by an open pull request are marked explicitly below and will change status as those merge. Findings here are a source-level reading of the code against the specification text, not a maintainer sign-off &mdash; review with the rt-libflute maintainers before treating any row as final.
:::

- **PR [#60](https://github.com/5G-MAG/rt-libflute/pull/60)** &mdash; FDT growth fixes, SSM, IPv4/IPv6 reception parity
- **PR [#61](https://github.com/5G-MAG/rt-libflute/pull/61)** &mdash; Raptor FEC (RFC 5053)
- **PR [#62](https://github.com/5G-MAG/rt-libflute/pull/62)** &mdash; RFC compliance fixes (TSI width, FDT Instance ID wraparound, Complete attribute, Close flags, EXT_FTI bootstrap)
- **PR [#64](https://github.com/5G-MAG/rt-libflute/pull/64)** &mdash; RaptorQ (reference only, not 3GPP)
- **PR [#65](https://github.com/5G-MAG/rt-libflute/pull/65)** &mdash; FLUTE version 2 transmit (reference only, not 3GPP)

Status used below: **Supported** (merged in `development`) &middot; **In review** (open PR) &middot; **Not yet supported** &middot; **Reference only** (deliberately outside the 3GPP profile).

## Protocol core: FLUTE/ALC/LCT

**Supported**

- FLUTE version 1 on transmit and receive (RFC 3926; mandated by TS 26.346 clause 7.2.0). The decoder additionally tolerates a version 2 EXT_FDT nibble on receive.
- Single FLUTE channel, single rate transport, no congestion control (TS 26.346 clauses 7.2.4, 7.3.2.2).
- LCT header per TS 26.346 clause 7.2.7: 32-bit CCI set to zero; 16-bit TSI (S=0, H=1); 16-bit TOI on transmit (O=0, H=1) with the decoder accepting up to 64-bit TOI; TOI 0 reserved for FDT Instances; Sender Current Time and Expected Residual Time flags zero; HDR_LEN in 32-bit words.
- LCT extension headers: EXT_FDT and EXT_FTI generated on every FDT Instance packet and on no file packets (clause 7.2.8); EXT_CENC decoded on receive, never generated (clause 7.2.8: FDT Instances shall not be content encoded); EXT_NOP/EXT_AUTH/EXT_TIME ignored on receive per RFC 3926 default handling.

**In review**

- Close Session (A) and Close Object (B) flags: read and settable, with a `close_session()`/`close_object(toi)` transmitter API and a receiver notification callback (PR #62; optional feature per clause 7.2.7).
- TSI values wider than 16 bits encoded with the LCT S flag (48-bit ceiling) instead of silently truncating (PR #62). Clause 7.2.7 fixes MBMS TSI at 16 bits, so a compliant MBMS session never triggers the wide encoding &mdash; this only removes a silent-truncation hazard.
- FDT Instance ID wraparound at 2<sup>20</sup> with expiry-aware reuse (PR #62; RFC 3926 clause 3.4.1 guidance).

**Not yet supported**

- EXT_TIME with ERT on transmit ("may" per clause 7.2.7).

## FEC (TS 26.346 clauses 7.2.2, 7.2.3, 7.2.12, Annex B)

**Supported**

- Compact No-Code FEC (RFC 3695, FEC Encoding ID 0), with blocking per the RFC 3926 "Algorithm for Computing Source Block Structure" (clause 7.2.3).
- FEC Payload ID as 16-bit SBN + 16-bit ESI, common to both schemes (clause 7.2.7).

**In review** (PR #61)

- Raptor FEC scheme (RFC 5053, FEC Encoding ID 1), encoder and decoder, implemented from scratch: systematic pre-coding, LT encoding, repair symbol generation, GF(2) decoding.
- Scheme-specific FEC OTI (Z, N, Al) carried in EXT_FTI and as FDT attributes, per RFC 5053 clause 3.2.3.
- Blocking per RFC 5053 clause 4.2 Partition function (clause 7.2.3).
- Once merged, this satisfies the UE mandate of clause 7.2.2: "A UE that supports MBMS User Services shall support a decoder for the Raptor FEC scheme."

:::caution[Known limitation]
Sub-blocking is fixed at N=1 on both sides. The receiver does not de-interleave N&gt;1 sub-blocks, so interoperability with a sender that sub-blocks is not provided. Clause 7.2.3 requires N, Z, T and A set such that the sub-block size stays below 256 KB; with N=1 the sub-block equals the source block, so a sender targeting the strict MBMS profile must bound `max_source_block_length` accordingly (K &times; T &le; 256 KB).
:::

**Reference only**

- RaptorQ (RFC 6330, FEC Encoding ID 6), full encoder/decoder with GF(256) linear algebra (PR #64). Not part of the TS 26.346 FEC scheme set; kept for non-3GPP deployments or future 3GPP adoption.

## FDT Instances (TS 26.346 clauses 7.2.9, 7.2.10)

**Supported**

- FDT XML namespaces: none, the RFC 3926 example namespace, `urn:IETF:metadata:2005:FLUTE:FDT` (the schema base of clause 7.2.10.1), and `urn:3GPP:metadata:2022:FLUTE:FDT` (clause L.6.1).
- Attributes read and written: Expires, TOI, Content-Location, Content-Length, Transfer-Length, Content-Type, Content-Encoding, Content-MD5 (verified on reception, mismatch triggers re-reception), FEC-OTI-FEC-Encoding-ID, FEC-OTI-FEC-Instance-ID, FEC-OTI-Maximum-Source-Block-Length, FEC-OTI-Encoding-Symbol-Length, FEC-OTI-Max-Number-of-Encoding-Symbols, and (PR #61) FEC-OTI-Number-Of-Source-Blocks / Number-Of-Sub-Blocks / Symbol-Alignment-Parameter, at both FDT-Instance and File level.
- 3GPP FDT extensions: `mbms2007:Cache-Control` (no-cache, Expires) and `mbms2012:File-ETag`, read and written.
- FDT Instance replacement by instance ID on the receiver; TOI reuse across instances detected by Content-Location change (stale in-progress receptions discarded).

**In review** (PR #62)

- Complete attribute (read/write).
- Receiver bootstrap of an object from a file packet's own EXT_FTI when the describing FDT has not (yet) arrived, with in-place metadata adoption when it does. Receive-side robustness only; 3GPP transmit behaviour is unchanged.

**Not yet supported**

- Group (clause 7.2.6), MBMS-Session-Identity and MBMS-Session-Identity-Expiry (clause 7.2.11), FullFDT (clause 7.2.14), Decryption-KEY-URI (clause 7.2.15), FEC-Redundancy-Level (clause 7.2.16), IndependentUnitPositions (Rel-13), Alternate-Content-Location-1/-2 and Base-URL-1/-2 (Rel-11), `mbms2007:max-stale`, the `sv:schemaVersion` element and version-based schema selection (clause 7.2.10.1).

:::caution[Known limitation]
Clause 7.2.9 states "the UE shall not use a received FDT Instance to interpret packets received beyond the expiration time." The Expires value is parsed and exposed, and expired files can be purged via the cache API, but packet interpretation is not hard-stopped at FDT expiry &mdash; enforcement today is partial.
:::

## Content encoding (TS 26.346 clause 7.2.5)

**Supported**

- GZIP (RFC 1952) encode on transmit and decode on receive, satisfying the UE mandate; deflate also handled. Decoded length is validated against Content-Length.
- FDT Instances are never content encoded on transmit (clause 7.2.8 mandate).

## Transport, session and platform

**Supported**

- UDP multicast transmit and receive, IPv4 and IPv6.
- Rate-limited single-rate transmission; FDT Instance carousel with configurable repeat interval.
- Transmitter source address selection and socket binding.
- UDP tunnel mode: encapsulated IPv4+UDP inner headers for delivery through a GTP-U user plane (the N3mb context of TS 23.247, used by rt-mbs-transport-function), and (PR #61) simultaneous plain + tunnelled transmission so direct SSM subscribers and the tunnel path are served at once.
- Graceful session control: activate/deactivate, deferred deactivation until queued files complete, completion callbacks on both sides.
- IPsec ESP protection of the transport (transmit and receive direction) via Linux XFRM/netlink.
- Promiscuous reception of all files announced in the FDT, with file expiry and cache management hooks (the one-copy and keep-updated download modes of clause 7.2.0 are application-side policies built on these hooks).

**In review** (PR #60)

- Source-Specific Multicast join (RFC 4607), IPv4 and IPv6.
- Multicast join on a specific interface; bind to ANY with membership on the selected interface.
- IPv4/IPv6 parity for all join paths; 64 KB receive buffer sized to the maximum UDP datagram (previously 2 KB, which silently truncated large encoding symbols).
- FDT growth fixes for carousel resends and content changes.

## Out of scope for the library

Handled by consuming projects, not rt-libflute:

- SDP session descriptions for FLUTE sessions (TS 26.346 clause 7.3): parsed/generated by rt-mbms-client, rt-mbs-client and the transport functions.
- Service announcement / User Service Description (clause 5.2).
- Associated delivery procedures: file repair (clause 9.3), reception reporting (clause 9.4), consumption reporting (clause 9.4A).
- OMA Push (clause 7.4), RTSP session control (clause 7.5), Keep Updated service (clause 7.7), partial file handling (clause 7.9).
- MBSTF/MBS service APIs (TS 29.581) and MBMS client APIs (TS 26.347).
