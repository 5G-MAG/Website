:::tip[In short]

- **What this covers:** the public warning chain of 5G Broadcast: the Cell Broadcast Centre (CBC), the broadcast transmitter, the MME and the alert receiver, judged against TS 23.041, TS 22.268, TS 29.168, ETSI TS 103 720, ETSI TS 102 900 (EU-Alert) and OASIS CAP v1.2.
- **What exists on `main`:** a CBC that takes warnings as JSON, builds the CAP record and sends the SBc-AP Write-Replace-Warning and Stop-Warning requests; and a web page that shows the alerts a modem decodes. The transmitter and the MME have no alert code.
- **Source of this page:** an audit of the `main` branch of each repository on 2026-10-21: every requirement split into the cases its clause defines, each case read against the code by one reader and then independently by a second, with a third reading where they disagreed. Cases that only a running system can settle are not shown.

:::

## What the Reference Tools implement

The Emergency Alerts work sits on the 5G Broadcast transmit chain, which is LTE based. Four roles are audited:

- **Cell Broadcast Centre (`rt-pws-cbc`):** receives a warning as JSON over HTTP, packs the headline and instruction as GSM 7-bit text, writes a CAP v1.2 record for each warning and sends the SBc-AP Write-Replace-Warning-Request and Stop-Warning-Request towards the MME. The interface to the cell broadcast entity is JSON, not CAP, and the CBC decodes nothing that comes back.
- **Transmitter (`rt-mbms-tx`, `rt-mbms-tx-for-qrd-and-crd`):** the srsRAN eNB builds the MBMS system information only. It has no handler for SIB10 to SIB12 or for ETWS and CMAS paging indications.
- **MME (srsepc in the two transmitter repositories):** handles S1 setup and a few S1AP messages. It has no SBc-AP interface towards a CBC.
- **Receiver (`rt-mbms-application`):** a web page that polls the modem and shows the current CMAS and ETWS alerts with a history, times and repeat count. Decoding, duplicate handling and message identification are in the modem, which is outside this audit.

What this means for a warning end to end: the CBC can produce and send a request, but nothing on `main` of the transmitter or the MME carries it on to the air interface.

- **Needs fix in the CBC:**
  - Warning content is sent as one unpaged GSM 7-bit string, not as CBS pages of 82 octets with a length octet and a language each.
  - The serial number is a plain counter, without geographical scope, message code and update number.
  - The CAP `<sent>` value carries milliseconds and a `+00:00` time zone, where CAP requires whole seconds and `-00:00`.
  - A polygon is accepted with three vertices and its closure is not checked.
  - The language is fixed and characters outside GSM 7-bit become `?`.
  - The default repetition period is 4096, above the maximum of 4095.
  - A success answer is returned whatever the MME replies.
- **Not implemented in the CBC:** paging, 8-bit and compressed content, the 5GS and PWS-IWF paths, and the SBc-AP error handling.
- **Not implemented in the receiver:** opt-in and opt-out, the dedicated alerting indication, location checks, URL and call actions, and dismissal of an alert.
