- **Which specification the code follows:** Release 17, TS 26.512 V17.10.0, for downlink 5GMS (5GMSd).
- **Release 18/19:** no component implements the TS 26.510 APIs or the Release 19 M3 API yet.

## Components

### Application Function (AF)

<RepoCards slugs={['rt-5gms-application-function']} />

- **Built against:** TS 26.512 V17.10.0 (Release 17). Serves `3gpp-m1/v2` and `3gpp-m5/v2`.
- **Implemented:** Provisioning Sessions, Content Protocols Discovery (HTTP pull ingest only), Server Certificates, M5 Consumption Reporting, Delivery Boost through the PCF.
- **Partial:** Content Hosting, Policy Templates, Consumption and Metrics Reporting provisioning, M5 Dynamic Policies, Network Assistance, Metrics Reporting and Service Access Information. PATCH is not supported; reports are written to local files.
- **Not implemented:** Content Preparation Templates, Content Publication, Edge Resources, Event Data Processing, bit rate recommendation, data reporting and event exposure (R4, R5, R6), the NEF path (N33), uplink, and the Release 19 Policy Template and Content Hosting additions.
- **M3:** Release 17 specifies no M3 API (TS 26.512 V17.10.0, clause 9). The AF uses `/3gpp-m3/v1` towards the first configured Application Server.

### Application Server (AS)

<RepoCards slugs={['rt-5gms-application-server']} />

- **Built against:** TS 26.512 Release 17 (V17.10.0 at the time of the audit).
- **Implemented:** HTTP pull-based ingest at M2d; M4d delivery as an HTTP and HTTPS caching proxy, with domain aliases and path rewrite rules.
- **Partial:** the M3 Server Certificates and Content Hosting configuration (`/3gpp-m3/v1`; Release 17 specifies no M3 API); CMCD reception at M4d, forwarded to the CMCD Toolkit.
- **Not implemented:** DASH-IF push and low-latency ingest, content preparation, M10 redistribution, Content Steering, CMMF, CPIX, uplink. Geo-fencing, URL signing and caching rules are accepted in a configuration but not applied.

### 5GMS client

<RepoCards slugs={['rt-5gms-media-session-handler', 'rt-5gms-media-stream-handler', 'rt-5gms-common-android-library', 'rt-5gms-application']} />

- **Built against:** Release 17, with the data models written by hand; the player is Media3 ExoPlayer.
- **Implemented:** DASH playback; M8 with a 5G-MAG `m8.json` service list.
- **Partial:** M5 Service Access Information, Consumption Reporting and Metrics Reporting (QM10 scheme, 8 metrics).
- **Not implemented:** HLS in the session path, Dynamic Policies and Network Assistance requests, 3GPP Service URL handling, DRM, Content Steering, CMMF, edge, eMBMS and MBS, uplink. M6 and M7 use a 5G-MAG interface between the application and the client services.
- **CMCD:** the player sends CMCD version 1 in query mode, on every request.

### Application Provider

<RepoCards slugs={['rt-5gms-application-provider']} />

- **Application Provider:** a Release 17 M1 client (`3gpp-m1/v2`) with command-line tools and management interfaces. It drives Provisioning Sessions, Content Protocols, Server Certificates, Content Hosting, Consumption Reporting, Metrics Reporting and Policy Templates. Content Preparation, Edge Resources, Event Data Processing and Content Publication are not implemented.

### Supporting repositories

These support the components above; the table does not rate them.

<RepoCards slugs={['rt-5gms-examples', 'cmcd-toolkit', 'rt-common-shared']} />

- **Examples:** Docker Compose recipes that deploy the AF, AS and Application Provider, with Open5GS.
- **CMCD Toolkit:** collector, storage (InfluxDB 1.8) and Grafana dashboards for the CMCD the AS forwards.
- **rt-common-shared:** the `/3gpp-m3/v1` definitions used by the AF and AS for M3, which Release 17 does not specify.
