:::tip[In short]

- **What the tools are:** reference tools for conversational avatars using MPEG ARF (ISO/IEC 23090-39) in a real-time call: a Unity call application, reference ARF content and a sample OpenXR tracker.
- **What this covers:** the call application (rt-avatar-call) as the AR-MTSI avatar client, judged against ETSI TS 26.264 V19.4.1 (Conversational Avatar Communication). Judged on the `main` branch of each repository on 2026-10-22.
- **Not covered:** the AR AS, the AR media function and the Base Avatar Repository have no code in any of the repositories, so their requirements are shown as not implemented. Cases that rest on ISO/IEC 23090-39, the MPEG_node_avatar extension of ISO/IEC 23090-14 and the IETF avatar RTP payload draft, which were not available, are not shown.
- **Source of this page:** every requirement is split into the cases its clause defines; each case was read against the code by one reader and then independently by a second, with a third reading where they disagreed.

:::

For what ARF and the call procedures define, see the [Technology](/tech/avatar) and the [Standards](/standards/avatar). For how to run the tools, see the [Tutorials](./tutorials) and the [Developer Exchange](./tutorials#developer-exchange).

## What the Reference Tools implement

- **Call application (rt-avatar-call):** a WebRTC call, signalled through SWAP, that carries audio and avatar animation. The animation units travel on a data channel with the `3gpp-ar-animation` sub-protocol, ordered and reliable. The receiving side applies them to the avatar; the avatar is loaded from a local file by a third-party ARF package. A webcam producer based on MediaPipe face landmarks generates the animation, and it is built only when that option is enabled.
- **AR metadata:** the `3gpp-ar-metadata` data channel is created, but the application sends no AR metadata over it, so metadata and rendering negotiation are not implemented.
- **Negotiation and signalling:** there is no IMS avatar call, no scene description, no `MPEG_node_avatar` use, no Base Avatar Repository access and no avatar negotiation; the client writes no avatar SDP attributes, and the compatibility check between the avatar and the animation producers is local only.
- **Network roles:** the AR AS, the media function and the Base Avatar Repository (with its Mbar_Management API) are not implemented in any repository.
- **Reference content and tracker:** rt-avatar-content holds ARF content and rt-avatar-unity-tracker holds the sample tracker; neither implements a specification requirement by itself.
