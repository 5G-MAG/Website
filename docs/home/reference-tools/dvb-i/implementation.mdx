:::tip[In short]

- **Which specification the code follows:** ETSI TS 103 770 V1.2.1 (2024-09), *Service Discovery and Programme Metadata for DVB-I*, with its schemas.
- **Status against TS 103 770:** {COUNT.reqs} requirements in {COUNT.cases} cases: {COUNT.implemented} implemented, {COUNT.differs} differ from the specification, {COUNT.absent} not implemented, and {COUNT.inconsistent} where the specification contradicts itself.
- **DVB-I over 5G**, in [its own section](#dvb-i-over-5g-status): {COUNT5G.reqs} requirements in {COUNT5G.cases} cases, judged against TS 103 770 clause 9.3, 3GPP TS 26.347 V18.1.0 and ETSI TR 103 972 V1.1.1 (informative, so judged as guidelines): {COUNT5G.implemented} implemented, {COUNT5G.differs} differ, {COUNT5G.absent} not implemented. The client checks and shows the 5G Broadcast signalling but reaches no MBMS Client. No component carries 5GMS Service Access Information, because no DVB or 3GPP element for it exists yet.
- **Source of this page:** a code audit of the repositories on 2026-10-02: each requirement split into the cases its clause defines, each case checked against the code, and the TS 103 770 cases of the client, provider and registry then re-checked by a second reader.

:::

## Components

### DVB-I client

<RepoCards slugs={['rt-dvb-i-application']} />

- **Built against:** TS 103 770 V1.2.1 (stated in the README; no build pin).
- **Implemented:** queries to a Service List Registry, with regulator lists first and a regulator list the default whenever there is one; Delivery, Language, TargetCountry and logos acted on; ServiceListId checked. One LCN table chosen by region, @visible, @selectable and LCNRange honoured, with target regions, subscription packages, parental ratings and linked applications. Service instances selected by clause 5.2.13, with @priority and its default of 0; caching and conditional requests. Content guide sources found by clause 6.1, with aligned 12 hour, now/next and pid requests, More Episodes and Box Sets with pagination, and programme ratings enforced. DASH instances and DVB-I Playlists played with dash.js.
- **TS 102 796:** HTTP caching by RFC 7234 (no-store, freshness from Age and Date) with conditional requests; the clause 11.2 TLS profile for every metadata connection (TLS 1.3 and 1.2, the table 15a suites, no forbidden signature, root keys of at least 112 bits); the launch location of linked applications and of XML AIT requests; XML AIT applications chosen by application type and the table 5 platform profile.
- **Specification inconsistent:** a response with both no-cache and max-age. RFC 7234 has it validated before each reuse, TS 103 770 clause 4.3.2.1 forbids a request before max-age has passed; this client follows TS 103 770.
- **Partial:** codecs and the encryption scheme are not checked in advance; after a 401 or 403 there are no credentials to present; plain HTTP endpoints are fetched with a warning, not only on the same private subnet; a service list on a local Media Server loads only when the deployment names that server as an exception.
- **Not implemented:** carriage in MBMS (clause 9.3) and the TS 26.347 MBMS Client APIs: for now no MBMS Client is reached from the browser. The client reads, checks and shows the 5G Broadcast signalling and plays a unicast instance of the service instead. It passes no MPD address to a 5GMSd-Aware Application.

### DVB-I over 5G Reference App (Android)

<RepoCards slugs={['rt-dvb-i-android-application']} />

- **Built against:** TS 103 770 V1.2.1 (stated in the README); Media3 ExoPlayer 1.10.0. The user interface is based on the design of 5G-MAGflix, the 5GMSd Aware Application in rt-5gms-application, by Daniel Silhavy (Fraunhofer FOKUS).
- **What it is:** a native Android DVB-I client that ports the logic of the DVB-I client above, audited with the other components. It has been run on a phone over Wi-Fi against the DVB-I examples, and its 122 unit tests pass.
- **Implemented:** service lists from a URL or a Service List Registry query, with a regulator list the default whenever there is one; LCN tables by region; service instances selected by clause 5.2.13; DASH and HLS played, with live and on-demand controls; access services, ratings and delivery shown as icons; the HTTP rules of clause 4.3; now/next, schedules, a programme guide grid and programme information; More Episodes, Box Sets and on-demand programmes; linked applications and DVB-I Playlists; plain HTTP only to the hosts named at build time, with a warning.
- **TS 102 796:** HTTP caching by RFC 7234 with conditional requests; the clause 11.2 TLS profile for metadata connections (TLS 1.3 and 1.2, the table 15a suites, certificates with an RSA key under 2 048 bits, a root under 112 bits or an MD5 or SHA-1 signature refused); the launch location of linked applications and of XML AIT requests; XML AIT applications chosen by application type and the table 5 platform profile; only JPEG and PNG images shown.
- **Partial:** in TLS 1.2 the platform still offers the rsa_pkcs1_sha1 signature algorithm, which table 15b forbids.
- **Specification inconsistent:** a response with both no-cache and max-age, as for the browser client; this client follows RFC 7234 and validates it before each reuse.
- **Not implemented:** HbbTV applications, Restart links, and a PIN for restricted content. 5G Broadcast signalling is read, checked and shown; the app is built in three variants: plain DVB-I, DVB-I as the MBMS-Aware Application through the 5G-MAG MBMS Middleware for Android (which does not yet expose an interface to bind to), and DVB-I as a 5GMSd-Aware Application. The two 5G variants are placeholders for now.

### Application Provider (service list and content guide)

<RepoCards slugs={['rt-dvb-i-application-provider']} />

- **Built against:** TS 103 770 V1.2.1; output checked against its schemas.
- **Implemented:** schema-valid service lists published as `application/vnd.dvb.dvbisl+xml`, with a new version on every change, JPEG or PNG logos, image variants, subscription packages, one LCN table per region and region selection by regionID. Delivery signalling, including a 5G Broadcast instance as `IdentifierBasedDeliveryParameters` holding its `mbms://` URL, checked against the TS 26.347 URL form on save and on restore so that an invalid one is never published, and @priority where one is configured. Content guide: ContentGuideSourceRef, timestamp, now/next and programme information requests, and the metadata profile, including a deep-linked XML AIT for on-demand programmes.
- **TS 102 796:** the clause 11.2 TLS profile when served over TLS, with ECDHE suites preferred; the content deep-linked XML AIT of clause 7.2.3.2 (application type, control code, one transport, length limits, media type), with the platform version 1.8.1 that table 5 sets; images only as JPEG or PNG, no GIF.
- **Partial:** served over TLS when a certificate is configured, otherwise plain HTTP with a warning. An `http:` URLBase in an XML AIT is published with a warning, where clause 11.9 advises `https:`. A 5G Broadcast instance is told apart from a unicast one only by its element and URL scheme.
- **Not implemented:** DVB-I Playlists, and 5GMS Service Access Information, which no DVB or 3GPP element yet carries in a service list.
- **Specification inconsistent:** the empty Schedule element and the programme image HowRelated term, where TS 103 770 contradicts itself.

### Service List Registry

<RepoCards slugs={['rt-dvb-i-service-list-registry']} />

- **Built against:** TS 103 770 V1.2.1; responses checked against `dvbi_service_list_discovery_v1.6.xsd`.
- **Implemented:** queries answered with schema-valid Service List Entry Points for every offering type, including offerings that leave a filter unspecified; invalid TargetCountry, Language and Genre values refused; the service list media type and @regulatorListFlag written; the Delivery values kept to those TS 103 770 defines.
- **TS 102 796:** the clause 11.2 TLS profile when served over TLS, with ECDHE suites preferred.
- **Partial:** served over TLS when configured, otherwise plain HTTP with a warning.
- **Specification inconsistent:** the image_variant query parameter, where TS 103 770 contradicts itself.

### Exo DVB-I Player

<RepoCards slugs={['rt-5gms-application']} />

- **Built against:** ExoPlayer r2.18.2; no DVB-I version stated. Audited at release v1.3.0.
- **What it is:** an Android WebView around an external DVB-I frontend, which is not 5G-MAG code, with ExoPlayer playing the DASH addresses the frontend requests.
- **Implemented:** playback of the intercepted MPD address; no retry after a 400 or 406.
- **Partial:** the service list is fetched from a fixed `http://` address, with no conditional request and Cache-Control not honoured.
- **Not implemented:** registry queries, service list handling, service instance selection and the content guide, which the external frontend does; MBMS carriage, the TS 26.347 APIs and 5G Media Streaming.

### Supporting repositories

These support the components above; the table does not rate them.

<RepoCards slugs={['rt-dvb-i-examples']} />
