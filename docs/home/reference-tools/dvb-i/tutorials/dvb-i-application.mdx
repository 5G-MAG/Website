The [DVB-I Application](https://github.com/5G-MAG/rt-dvb-i-application) is a DVB-I client that runs in a web browser. It finds a service list, shows its channels with their programme guide, and plays them (ETSI TS 103 770 V1.2.1, the client side of clause 4.1). In this tutorial you run it, open a public service list, open the list you publish yourself, find a list through a Service List Registry, and read the guide.

:::tip[Read the READMEs first]
Read the README of [rt-dvb-i-application](https://github.com/5G-MAG/rt-dvb-i-application#readme) before you start; `DEPLOYMENT.md` in the same repository gives every setting. The other repositories below are only needed in the sections that name them.
:::

**You need:** a Linux machine with `git`, Node.js 20 or later with `npm`, `curl` and a browser (Chrome, Edge or Firefox); about 25 MB of disk and a connection to the internet, because the client loads its two player libraries from a CDN and section 1 opens a list published elsewhere. Sections 3 and 4 also need the provider and the registry running, which the two other tutorials set up.

## 1. Run the client

```bash
cd ~
git clone https://github.com/5G-MAG/rt-dvb-i-application.git
cd rt-dvb-i-application
npm install
npm start
```

```text
{"time":"2026-10-21T19:06:51.533Z","level":"warn","msg":"/proxy will follow these origins without the private-address check","origins":["http://localhost:4000","http://127.0.0.1:4000"],"source":"default (PROXY_ALLOW_ORIGINS not set)"}
{"time":"2026-10-21T19:06:51.535Z","level":"info","msg":"DVB-I Client listening (http)","port":5000}
DVB-I Client      →  http://localhost:5000
```

The first line says which local addresses the client's server may fetch lists from (section 3 explains it). Open `http://localhost:5000` in a browser. The client first tries the provider on your own machine, which is not set up yet (section 3), so the sidebar says `Load failed` and the list shows `Error: HTTP 502 for http://localhost:4000/service-list.xml: TypeError: fetch failed`. Press the gear icon at the top of the sidebar (or the **S** key) to open the settings, and under **Service list URL** press the **dtv.fi** button. It loads the list that Sofia Digital publishes at `https://dvbi-rest.dtv.fi/services_r4/DVBI(epg)`.

The sidebar shows the name of the list, `DVBI(epg)`, and its channels with their channel numbers (eleven when this page was written). Press a channel to play it.

## 3. Open your own service list

Run the provider of [Tutorial: DVB-I Application Provider](./application-provider), sections 1 and 3, so that `http://localhost:4000/service-list.xml` answers.

The client reaches service lists through its own server (`/proxy`), because a browser cannot fetch most lists across origins. That server refuses addresses on your own machine unless their origin is named in `PROXY_ALLOW_ORIGINS`. When the variable is not set, it allows the origin of the provider's default address, `http://localhost:4000` and `http://127.0.0.1:4000`, so the client you started in section 1 can load the provider's list as it is. Open the list by its address:

`http://localhost:5000/?url=http://localhost:4000/service-list.xml`

The `url` in the address is the service list to load; the client remembers it in the browser for the next visit. (A browser that remembers no other list opens the provider's list at `http://localhost:5000/` with nothing added; yours remembers the **dtv.fi** list from section 1, which is why the address above names the list.)

The sidebar shows `5G-MAG`, the name of the stock list, and its channels. If you did section 3 of the provider tutorial, channel 4 is `Tutorial Channel`, with the programme that is on now. Select it, or press **4**. The strip under the player shows **Now** and **Next** from the provider's programme guide, and **E** opens the full schedule.

To change something and see it arrive, edit a channel in the provider's admin portal (`http://localhost:4000/`), press **Save & Publish**, and reload the client page.

:::tip[A list on another address of your machine]
For any local address other than the provider's default, name its origin: `PROXY_ALLOW_ORIGINS="http://localhost:4000,http://192.168.1.20:8080" npm start`. Setting the variable replaces the default, so name the provider's origin too when you still need it, and an empty value allows no local origin at all (what a public deployment should use). When the client's server refuses an address, the sidebar shows `Load failed` and `Error: HTTP 400`, with a hint that names the setting. A list on another machine needs nothing.
:::

## 4. Find a list through a registry

A client that is given no list address asks a Service List Registry for the lists of a country. Run the registry of [Tutorial: DVB-I Service List Registry](./service-list-registry), with the second list of its section 3. The registry is on port 7000, which is not among the default origins, so stop the client with Ctrl+C and start it again with the provider's and the registry's origins:

```bash
PROXY_ALLOW_ORIGINS="http://localhost:4000,http://localhost:7000" npm start
```

1. Open `http://localhost:5000` and open the settings.
2. Under **Service List Registry**, the first box is empty: the client has no default registry address, because none is named by TS 103 770 or TR 103 972. Type `http://localhost:7000/query`. The client remembers it. (If you press **Look up** with the box empty, the client says `No Service List Registry address is set.` and tells you to enter one.)
3. In the second box type the country code `CHE` and press **Look up**.

The client sends `GET /query?TargetCountry=CHE` to the registry. The registry holds two lists for Switzerland, so the client offers both under **Found 2 service lists**:

![The settings panel after a look-up: two service lists to choose from](/img/dvb-i/tut-dvbi-client-lookup.png)

4. Press `5G-MAG`, the entry of the stock registry. The client loads the list from the address the registry gave and shows its channels. The second entry, `DVB-I Demo Service List`, points at the same address, so it shows the same channels.

With one match the client loads the list at once. If a registry lists several addresses for the same list, the client keeps them as fallbacks.

:::note[A registry that does not answer]
If the look-up fails, the settings panel shows the reason: for example `HTTP 400 ... disallowed (private/loopback) address` when the registry's origin is not in `PROXY_ALLOW_ORIGINS`. Check the address in the box, then the registry itself with `curl -s 'http://localhost:7000/query?TargetCountry=CHE'`.
:::

## 5. Check it

To see which requests the client made for your list, open the browser's developer tools on the **Network** tab and reload: the service list and the programme guide go to `/proxy?url=...` on port 5000, the logos, the stream manifests and the segments go straight to the servers named in the list.

To confirm that the client's server can reach a list, without the browser:

```bash
curl -s 'http://localhost:5000/proxy?url=http://localhost:4000/service-list.xml' | head -3
```

```text
<?xml version="1.0" encoding="UTF-8"?>
<ServiceList
  xmlns="urn:dvb:metadata:servicediscovery:2024"
```

If it answers `{"error":"URL resolves to a disallowed (private/loopback) address","hint":...}` the origin is not allowed: name it in `PROXY_ALLOW_ORIGINS` (the hint says how).

The repository has unit tests and browser tests:

```bash
npm run test:unit
```

The unit tests finish with `pass 9` and `fail 0`. `npm test` also runs the browser tests; they need a Playwright browser, installed once with `npx playwright install chromium`, and use Firefox when you set `BROWSER=firefox`. With the browser installed, `npm test` finishes with `pass 29` and `fail 0`.

## 6. Stop and clean up

Press Ctrl+C in the terminal of the client. To remove it, delete `~/rt-dvb-i-application`.
