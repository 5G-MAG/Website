A DVB-I client has to find service lists before it can show any channel. The [DVB-I Service List Registry](https://github.com/5G-MAG/rt-dvb-i-service-list-registry) is the component it asks: an HTTP endpoint that answers a query with the entry points of the service lists that match it (ETSI TS 103 770 V1.2.1, clause 5.1.3.2). In this tutorial you run the registry, send it the queries of that clause, register a service list of your own, and check what it answers against the DVB-I schema.

:::tip[Read the READMEs first]
Read the README of [rt-dvb-i-service-list-registry](https://github.com/5G-MAG/rt-dvb-i-service-list-registry#readme) before you start. The other repositories below are only needed in the sections that name them.
:::

**You need:** a Linux machine with `git`, Node.js 20 or later with `npm`, and `curl`; about 30 MB of disk. For section 5 you also need `python3` with the `venv` module and the DVB-I schema files (see that section).

## 1. Run the registry

```bash
cd ~
git clone https://github.com/5G-MAG/rt-dvb-i-service-list-registry.git
cd rt-dvb-i-service-list-registry
npm install
npm start
```

The registry prints where it listens (the first line is a log record, so its time differs):

```text
{"time":"2026-10-20T22:36:22.147Z","level":"info","msg":"Service List Registry listening","port":7000}
DVB-I Service List Registry  ->  http://localhost:7000/query
```

In a second terminal, ask it for the service lists that target Switzerland:

```bash
curl -s 'http://localhost:7000/query?TargetCountry=CHE'
```

```xml
<?xml version="1.0" encoding="UTF-8"?>
<ServiceListEntryPoints
  xml:lang="en"
  xmlns="urn:dvb:metadata:servicelistdiscovery:2024"
  xmlns:dvbisd-t="urn:dvb:metadata:servicediscovery-types:2023"
  xmlns:mpeg7="urn:tva:mpeg7:2008"
  xmlns:tva="urn:tva:metadata:2024">
  <ServiceListRegistryEntity>
    <Name>5G-MAG Reference Service List Registry</Name>
  </ServiceListRegistryEntity>
  <ProviderOffering>
    <Provider>
      <Name>5G-MAG</Name>
    </Provider>
    <ServiceListOffering>
      <dvbisd-t:ServiceListName>5G-MAG</dvbisd-t:ServiceListName>
      <dvbisd-t:ServiceListURI contentType="application/vnd.dvb.dvbisl+xml">
        <dvbisd-t:URI>http://localhost:4000/service-list.xml</dvbisd-t:URI>
      </dvbisd-t:ServiceListURI>
      <dvbisd-t:Delivery>
        <dvbisd-t:DASHDelivery/>
      </dvbisd-t:Delivery>
      <dvbisd-t:Language>en</dvbisd-t:Language>
      <dvbisd-t:TargetCountry>CHE</dvbisd-t:TargetCountry>
      <dvbisd-t:TargetCountry>DEU</dvbisd-t:TargetCountry>
      <dvbisd-t:TargetCountry>ESP</dvbisd-t:TargetCountry>
      <dvbisd-t:ServiceListId>tag:5g-mag.org,2026:servicelist:local-demo</dvbisd-t:ServiceListId>
    </ServiceListOffering>
  </ProviderOffering>
</ServiceListEntryPoints>
```

That is a Service List Entry Point: the name of a list, the URL where a client fetches it, and what it delivers. The `contentType` of the URI is the media type of a Service List, `application/vnd.dvb.dvbisl+xml` (TS 103 770 V1.2.1, clauses 5.1.2 and 5.3.5, table 22). The entry in the stock file points at `http://localhost:4000/service-list.xml`, where the [DVB-I Application Provider](./application-provider) publishes its list, and it carries the name `5G-MAG` and the identifier of that provider's stock list.

Ask for a country nothing targets:

```bash
curl -s 'http://localhost:7000/query?TargetCountry=ITA'
```

The answer is a valid document with the `ServiceListRegistryEntity` and no `ProviderOffering`, as clause 5.1.3.2 requires when nothing matches.

:::tip[Leave the registry running]
Sections 2 to 5 use this terminal's registry. Stop it with Ctrl+C when you reach [section 7](#7-stop-and-clean-up).
:::

## 2. The page at /

Open `http://localhost:7000/` in a browser. The page lists what the registry holds, one row for each service list, and has a form for the queries of clause 5.1.3.2: type a country code, choose a delivery type, a provider and the regulator flag, then press **Run**. It shows the address it called and the response.

![The registry page with two service lists and the response to TargetCountry=FRA](/img/dvb-i/tut-dvbi-registry-page.png)

The page is read only. The registry holds its entries in `registry.json`, and you change them there, as the next section shows.

## 3. Register a service list

Clause 5.1.3.2 leaves open how a registry collects and stores the entry points of the providers, so the repository keeps them in one file, `registry.json`. The registry reads it on every request: you edit it and query again, with no restart.

Open `registry.json`. Under `providers` is a list of providers, each with its `offerings`. Add a provider after the existing one:

```json
    {
      "name": "Example Media",
      "offerings": [
        {
          "id": "tag:example.com,2026:servicelist:tutorial",
          "name": "DVB-I Demo Service List",
          "uris": ["http://localhost:4000/service-list.xml"],
          "delivery": ["dash"],
          "languages": ["en", "fr"],
          "genres": [],
          "countries": ["CHE", "FRA"],
          "regulator": false,
          "extensions": []
        }
      ]
    }
```

| Field | What to put |
|---|---|
| `id` | The identifier of your service list. It should be the `id` attribute of the list itself and never change (TS 103 770 V1.2.1, clause 5.3.5, table 12, `ServiceListId`) |
| `name` | The name of the list. It shall be the same as the `Name` element of the list (same table, `ServiceListName`) |
| `uris` | The URL or URLs where a client fetches the list |
| `delivery` | One or more of `dash`, `dvb-t`, `dvb-c`, `dvb-s`, `rtsp`, `multicast-ts`, `application` |
| `languages`, `countries` | Audio languages (`en`) and countries (ISO 3166 alpha-3 such as `FRA`) the list targets. An offering with none is returned for every value of that parameter |
| `genres`, `regulator`, `extensions` | Leave as shown. `regulator` is `true` only for the list a national regulator publishes |

The stock entry already matches the stock list of [Tutorial: DVB-I Application Provider](./application-provider): the same name (`5G-MAG`) and the same identifier. The entry above only shows how an offering is written; it points at the same address as the stock one. For a list of your own, use the name and the `id` that the provider shows for it in the Service List Settings. A client may compare the `id` of an offering with the `id` of the list it fetches (table 12, `ServiceListId`).

Check that the registry now offers it:

```bash
curl -s 'http://localhost:7000/query?TargetCountry=FRA' | grep -E 'ServiceListName|ServiceListId|URI>'
```

```text
      <dvbisd-t:ServiceListName>DVB-I Demo Service List</dvbisd-t:ServiceListName>
        <dvbisd-t:URI>http://localhost:4000/service-list.xml</dvbisd-t:URI>
      </dvbisd-t:ServiceListURI>
      <dvbisd-t:ServiceListId>tag:example.com,2026:servicelist:tutorial</dvbisd-t:ServiceListId>
```

If the file is not valid JSON the registry answers `500 Registry unavailable` and logs the reason, so a typo shows at once.

## 4. Query it

Every recipe is `curl -g -s '<registry>/query?<parameters>'`. The `-g` lets `curl` take the square brackets as they are. The parameters are those of clause 5.1.3.2, in the order it lists them: `TargetCountry`, `regulatorListFlag`, `Delivery`, `Language`, `Genre`, `ProviderName`, `inlineImages`.

| You want | Query | Offerings returned with the two lists of section 3 |
|---|---|---|
| The lists for one country | `TargetCountry=CHE` | 2 |
| One country only the new list has | `TargetCountry=FRA` | 1 |
| Either of two countries | `TargetCountry[]=CHE&TargetCountry[]=FRA` | 2 |
| One provider | `ProviderName=Example%20Media` | 1 |
| One audio language | `Language=fr` | 1 |
| A country and a delivery method together | `TargetCountry=FRA&Delivery=dvb-t` | 0 |

Repeated values of one parameter are alternatives (OR); different parameters narrow the result together (clause 5.1.3.2). The `Delivery` values are those of table 12b: `dvb-dash`, `dvb-t`, `dvb-c`, `dvb-s`, `dvb-iptv` and `application`, not the names used in `registry.json`.

**Check:** count the offerings in an answer.

```bash
curl -g -s 'http://localhost:7000/query?TargetCountry[]=CHE&TargetCountry[]=FRA' | grep -c '<ProviderOffering>'
```

```text
2
```

**Wrong queries are refused**, as the clause requires:

```bash
curl -s -w '\n%{http_code}\n' 'http://localhost:7000/query?Foo=1'
curl -s -w '\n%{http_code}\n' 'http://localhost:7000/query?Delivery=dvb-xx'
```

```text
Unknown query parameter "Foo". Accepted, in this order: TargetCountry, regulatorListFlag, Delivery, Language, Genre, ProviderName, inlineImages.
400
Invalid Delivery "dvb-xx". Accepted: dvb-dash, dvb-t, dvb-c, dvb-s, dvb-iptv, application.
400
```

A request URL longer than 2 048 characters, the limit of the clause, gets `414`.

## 5. Check a response against the schema

A registry answer is a `ServiceListEntryPoints` document. Its schema is `dvbi_service_list_discovery_v1.6.xsd` (TS 103 770 V1.2.1, clause 5.3.1 and annex B). The repository does not carry schema files; you supply them from a folder outside the clone.

1. Get the schema files. They come with the specification, in the electronic attachment archive `ts_103770v010201p0.zip` of ETSI TS 103 770 V1.2.1 (annex B). The folder needs `dvbi_service_list_discovery_v1.6.xsd` and the files it imports: `dvbi_types_v1.0.xsd`, `tva_metadata_3-1.xsd` and `tva_mpeg7.xsd` from the archive, and `xml.xsd` from the W3C, which is not in the archive. The repository's README ("Where the schema files come from") gives the same steps:

   ```bash
   mkdir -p ~/dvb-i-schemas && cd ~/dvb-i-schemas
   curl -L -A "Mozilla/5.0" -O https://www.etsi.org/deliver/etsi_ts/103700_103799/103770/01.02.01_60/ts_103770v010201p0.zip
   unzip -j ts_103770v010201p0.zip '*.xsd' -x 'xmlait/*' -d .
   curl -L -A "Mozilla/5.0" -o xml.xsd https://www.w3.org/2001/xml.xsd
   ```
2. Run the repository's own check:

   ```bash
   DVBI_SCHEMAS=~/dvb-i-schemas npm run test:xsd
   ```

   ```text
   + fixture, no query parameters: VALID
   + fixture, TargetCountry=ITA: VALID
   + fixture, regulatorListFlag=true: VALID
   + fixture, Delivery[]=dvb-dash&Delivery[]=dvb-t: VALID
   + fixture, no matches: VALID
   + registry.json as shipped: VALID
   ~ fixture + LOCAL 5G delivery extension: NOT CHECKED — carries the LOCAL 5G delivery extension
       (set DVBI_5G_EXT_SCHEMA to dvbi-5g-ext-1.0.xsd to check it)

   ==== ALL VALID (1 not checked, see above) ====
   ```

3. Check any answer yourself. Save this as `check.py` outside the clone:

   ```python
   import sys
   from lxml import etree

   schema_file, doc_file = sys.argv[1], sys.argv[2]
   schema = etree.XMLSchema(etree.parse(schema_file))
   doc = etree.parse(doc_file)
   if schema.validate(doc):
       print("VALID:", doc_file)
   else:
       print("INVALID:", doc_file)
       for error in schema.error_log:
           print(f"  line {error.line}: {error.message}")
       sys.exit(1)
   ```

   ```bash
   python3 -m venv ~/dvbi-check
   ~/dvbi-check/bin/pip install lxml
   curl -g -s 'http://localhost:7000/query?TargetCountry[]=CHE&TargetCountry[]=FRA' > answer.xml
   ~/dvbi-check/bin/python check.py ~/dvb-i-schemas/dvbi_service_list_discovery_v1.6.xsd answer.xml
   ```

   ```text
   VALID: answer.xml
   ```

:::note[The ETSI download]
The run for this page used the archive from ETSI, as in the commands above. A plain `curl` of that address was refused with HTTP 403 in an earlier run and answered 200 on 2026-10-21; the `-A "Mozilla/5.0"` option and a browser download both worked. If your download is refused, use one of those.
:::

## 6. Configure it

The registry reads three environment variables (README):

| Variable | Default | What it does |
|---|---|---|
| `PORT` | `7000` | The port it listens on |
| `REGISTRY_PATH` | `registry.json` | The registry file to read |
| `LOG_LEVEL` | `info` | `error`, `warn`, `info` or `debug` |

For example, a second registry with its own file on another port:

```bash
cp registry.json ~/my-registry.json
PORT=7001 REGISTRY_PATH=$HOME/my-registry.json npm start
```

:::note[TLS beyond a private network]
TS 103 770 V1.2.1, clause 7.3, says a DVB-I client uses HTTP over TLS to reach a Service List Registry, and allows plain HTTP only when the registry is on the same private subnet as the client. The registry listens on plain HTTP, so for a client on another network put a reverse proxy that terminates TLS in front of it.
:::

## 7. Stop and clean up

Press Ctrl+C in the registry's terminal. To remove it, delete `~/rt-dvb-i-service-list-registry`, `~/dvb-i-schemas` and `~/dvbi-check`.

To see a client use your registry, follow [Tutorial: DVB-I Application](./dvb-i-application), section 4.
