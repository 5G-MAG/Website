  const features = AUDIT.features.filter(keep);
  const reqs = features.flatMap((f) => f.requirements);

  return {
    ...AUDIT,
    features,
    components: pick(AUDIT.components, new Set(reqs.map((r) => r.component))),
    releases: pick(AUDIT.releases, new Set(reqs.map((r) => r.release))),
    releaseNames: pick(AUDIT.releaseNames || {}, new Set(reqs.map((r) => r.release))),
  };
};
export const US = part((f) => f.requirements.every((r) => r.release === 'US18'));
export const SYS = part((f) => f.requirements.some((r) => r.release !== 'US18'));
export const count = (data) => {
  const reqs = data.features.flatMap((f) => f.requirements);
  const cases = reqs.flatMap((r) => r.cases);
  const n = (v) => cases.filter((c) => c.verdict === v).length;
  return { reqs: reqs.length, cases: cases.length, implemented: n('implemented'), differs: n('differs'), absent: n('absent'), inconsistent: n('inconsistent') };
};
export const CUS = count(US);
export const CSYS = count(SYS);

:::tip[In short]

- **Which specifications the code is judged against:** the latest Release 18 issue of each: for MBS User Services, 3GPP TS 26.502 V18.6.0, TS 26.517 V18.6.0, TS 29.580 V18.8.0 and TS 29.581 V18.6.0; for MBS, TS 23.247 V18.8.0 with TS 29.532 V18.6.0, TS 29.518 V18.15.0 and TS 29.244 V18.10.0, and for NG-RAN TS 38.300, TS 38.331, TS 38.413 and TS 38.473 V18.11.0. What each component is built against is given under Components.
- **[MBS User Services](#mbs-user-services):** {CUS.reqs} requirements in {CUS.cases} cases: {CUS.implemented} implemented, {CUS.differs} differ from the specification, {CUS.absent} not implemented, and {CUS.inconsistent} where the specification contradicts itself.
- **[MBS](#mbs) (5G System and NG-RAN):** {CSYS.reqs} requirements in {CSYS.cases} cases: {CSYS.implemented} implemented, {CSYS.differs} differ, {CSYS.absent} not implemented. MBS Broadcast is covered; MBS Multicast is mostly not implemented.
- **Source of this page:** a code audit of the repositories on 2026-10-03: each requirement split into the cases its clause defines, each case checked against the code, then every case that is not implemented, and a third of the others, re-checked by a second reader. The FLUTE library (rt-libflute) is audited separately.

:::

For what the specifications define, see the [Technical Analysis](/tech/5g-mbs). For how to run the tools, see the [Application Showcase](/reference-tools/5g-mbs/tutorials).

## Components

### MBS User Services

#### MBS Function (MBSF)

<RepoCards slugs={['rt-mbs-function']} />

- **Built against:** 5G_APIs tag TSG111-Rel18: Nmbsf MBSUserService 1.1.0 and MBSUserDataIngestSession 1.1.2 (TS 29.580 V18.7.0), Nmbstf 1.1.1 (TS 29.581 V18.6.0); judged against TS 29.580 V18.8.0.
- **Implemented:** both Nmbsf APIs at Nmb10, every resource and method, with status subscriptions and notifications; the Nmbstf requests towards the MBSTF at Nmb2; the User Service Description, Session Description documents, the User Service Descriptions bundle and the announcement channel; the co-located MBS AF serving announcements at MBS-5; TMGI allocation and MBS session creation towards the MB-SMF at Nmb1.
- **Partial:** the enhanced PATCH of TS 29.580 V18.8.0 is not supported; four status events can be subscribed to but are never raised; the Distribution Session life-cycle differs from TS 26.502 clause 4.6.1; several Distribution Session and schedule attributes are not written; the announcement passed back to the Application Provider at MBS-1 carries a URL instead of the identifiers.
- **Specification inconsistent:** the repair locator attribute, and an empty discovery result at MBS-5, where the TS 26.517 text contradicts itself.

#### MBS Transport Function (MBSTF)

<RepoCards slugs={['rt-mbs-transport-function']} />

- **Built against:** 5G_APIs tag TSG111-Rel18 (TS 29.581 V18.6.0); FLUTE through rt-libflute.
- **Implemented:** the Nmbstf_MBSDistributionSession API at Nmb2, every resource and method, with StatusNotify; the Object Distribution Method operating modes; object ingest at Nmb8 by pull and push; transmission towards the MB-UPF at Nmb9.
- **Partial:** collection objects are distributed again on every refresh; pull fetches have no address when no ingest base URL is given; streaming segments are fetched too late for their deadline; manifest and update-interval rules differ; the Distribution Session life-cycle follows only what the MBSF requests.
- **Not implemented:** DSCP marking, FEC for packet sessions, and HTTPS on the push ingest endpoint.
- **Specification inconsistent:** the API name, who nominates the push ingest URL, and whether the SSM port is the source or the destination port.

#### MBS Client

<RepoCards slugs={['rt-mbs-client']} />

- **Built against:** TS 26.517 V18.6.0 annex A.2 (announcement parsing written by hand); FLUTE through rt-libflute.
- **Implemented:** User Service Description acquisition, reception activation and termination, Session Description handling, post-session object repair at MBS-4-UC, and delivery to the MBS-Aware Application at MBS-7.
- **Partial:** object repair opens a connection and sends a request per range, and draws the repair server again for each object; retrieval by identifier at MBS-5 is written but not called.
- **Not implemented:** MBS Service Key retrieval from the MBSSF at MBS-10, the Packet Distribution Method, and a User-Agent on the client's requests.

#### MBS Application Provider and MBS-Aware Application

<RepoCards slugs={['rt-mbs-application-provider', 'rt-mbs-application']} />

- **Application Provider, implemented:** MBS User Service and MBS User Data Ingest Session provisioning at Nmb10, adding and removing Distribution Sessions through its API, status subscriptions, and content ingest at Nmb8.
- **Application Provider, partial:** it sends attributes that only the MBSF may set or that may not be changed, does not check the object acquisition identifiers against the operating mode, and connects to the MBSF without TLS; the enhanced PATCH of TS 29.580 V18.8.0 is not used.
- **MBS-Aware Application:** it lists announced services and activates reception through the MBS Client; it activates only by external service identifier, with no way to pass a full announcement.

### MBS

#### 5G Core with MBS components

<RepoCards slugs={['open5gs', 'rt-5gc-service-consumers']} />

- **Built against:** OpenAPI models generated from the Release 17 files (TS 29.532 V17.3.0, TS 29.518 V17.9.0), with some Release 18 fields added by hand; NGAP ASN.1 V17.3.0; PFCP from TS 29.244 V17.7.1. The audit judges against Release 18.
- **Implemented:** TMGI allocation and deallocation at the MB-SMF; MBS session creation and release; the N4mb PFCP session between MB-SMF and MB-UPF; the AMF broadcast context and NGAP Broadcast Session Setup towards NG-RAN; the MB-SMF client library used by the MBSF.
- **Partial:** the MB-SMF stores the wrong cells of a service area and sets up a larger area than it reports; the AMF sends Broadcast Session Setup to every connected gNB; one QoS flow per session; the TEID signalled to NG-RAN is byte-reversed against the one in the GTP-U header.
- **Not implemented:** status subscriptions at the MB-SMF, several session update fields, N3mb unicast transport and PFCP Session Modification, NGAP Broadcast Session Release Required and Transport at the AMF, and MBS Multicast (session join and leave, Distribution Setup and Release).

#### NG-RAN and UE with MBS components

<RepoCards slugs={['srsRAN_Project_mbs', 'srsRAN_4G_mbs']} />

- **Built against:** generated codecs NGAP v17.4.0, F1AP v17.4.1, E1AP v18.5.0 and RRC v17.4.0 in the gNB, with some Release 18 content added by hand; in the UE, MBS types added by hand to its RRC codec. The audit judges against the latest Release 18 issues.
- **gNB, implemented:** NGAP Broadcast Session Setup, Modification and Release; the F1AP broadcast context and E1AP broadcast bearer context procedures; SIB1, SIB20 and MCCH scheduling with the modification period; DCI format 4_0; MTCH on its G-RNTI.
- **gNB, partial:** MCCH is sent with no MAC subheader and no RLC header; its repetition period is not used; failure messages leave out their cause or the failed bearers; the N3mb TEID is byte-reversed to match the 5G Core.
- **UE, implemented:** SIB20 acquisition, DCI format 4_0 reception, broadcast MRB establishment and release, RLC UM and PDCP for MTCH.
- **UE, partial:** MCCH is read without its MAC and RLC headers, and its change notification is not read; default PDCP and RLC timers differ from TS 38.331 clause 9.1.1.7; MRBs are told apart by logical channel alone.
- **Not implemented:** NGAP Broadcast Session Release Required and Transport, F1AP Broadcast Context Release Request and Broadcast Transport Resource Request, the Release 18 Supported UE Type List and Associated Session ID, broadcast DRX, and MBS Multicast in the RAN, including multicast in RRC_INACTIVE.
- **gNB, also partial:** the Broadcast Area Scope is not returned to the gNB-CU, and the MBS Service Area on modification is ignored.
