:::tip[In short]

- **Which specification the code follows:** the Release 18 API definitions of TS 26.532 as published by 3GPP at its TSG meeting 105, which is the default of the build. The audit judges every statement of TS 26.531 and TS 26.532 valid in Releases 17 to 19 (no Release 20 change is known).
- **Generic framework:** a Data Collection AF library and a standalone AF serve R1, R2 to R4, R5 and R6. No data collection client is provided.
- **In 5G Media Streaming:** the Data Collection AF library is designed to be embedded in the 5GMS Application Function. That integration is not yet part of the main branch of the 5GMS Application Function, so no 5GMS data is collected or exposed yet.
- **Source of this page:** an audit of the `main` branch of the Data Collection AF repository on 2026-10-20: each requirement split into the cases its clause defines, each case read against the code by one reader and then independently by a second, with a third reading where they disagreed. Cases that depend on the Open5GS framework layer, which is not part of the repository, are not shown.

:::

For what the specifications define, see the [Technology](/tech/data-collection/overview). For how to run the tools, see the [Tutorials](/reference-tools/data-collection/tutorials). The Standards are on the [Data Collection standards page](/standards/data-collection).

The Data Collection AF library is designed to be embedded in the 5GMS Application Function; that integration is not yet merged into the main branch of the 5GMS Application Function. See the [5G Media Streaming: Implementation Detail](/reference-tools/5gms/implementation) page for the 5GMS side.

## Implementation status

The Data Collection AF (repository cards are on the [project page](/reference-tools/data-collection#repositories--releases)).

- **Implemented:** creating, reading and deleting Provisioning Sessions, Data Reporting Configurations and Data Reporting Sessions; communication reports; time-window aggregation; context identifiers on rules and conditions; event subscription and notification at R5 and R6; registration of an AF profile with the NRF at start-up.
- **Needs fix:** replacing a Data Reporting Configuration does not store it; the code returns 201 (Created) when a session or configuration is read, where the specification gives 200 (OK); the aggregation function names MAXIMUM and MINIMUM of the specification are not accepted (the code expects MIN and MAX), and COUNT is not accepted for communication records; an empty list of event consumer types matches no consumer; the event time stamp is the time of the notification, not of the record; default values for omitted sampling and reporting rules are not applied; a few property names differ from the specification (`location`, `downlinkThrougput`).
- **Not implemented:** PATCH, user and location restrictions, record types other than communication (a report with another type is accepted and not stored), redirects, the CORS headers, updating the NRF profile when provisioning changes, and a Direct, Indirect or AS data collection client.

## Used with other projects

The Data Collection AF library is designed to be used by the [5G Media Streaming](/reference-tools/5gms) Application Function; see the 5G Media Streaming section above for the state of that integration.
