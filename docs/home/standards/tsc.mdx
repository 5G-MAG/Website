<h1>Time-Sensitive Communications (TSC)</h1>

5G-MAG monitors standardisation of Time Sensitive Communication (TSC) and its application to media production workflows, such as SMPTE ST 2110 essence transport. For how TSC works, see the [Technology page](/tech/tsc).

TSC in a media context usually runs over a private 5G deployment. For the network foundations it depends on, see [Non-Public Networks: Specifications](/standards/npn) first.

5G-MAG tracks how these deterministic-delivery and time-synchronisation capabilities apply to professional media, in particular the transport of SMPTE ST 2110 essence over private 5G, the alignment of the 5G and PTP time domains, and the combination with Non-Public Networks.

:::tip[At a glance]

- **Layers:** the 3GPP service requirements and system architecture, the IEEE 802.1 Time-Sensitive Networking standards that 5G TSC interworks with, and the SMPTE standards for IP media production.
- **By release:** Release 16 makes the 5G system a TSN bridge; Release 17 adds generalised time synchronisation and the TSCTSF; Release 18 adds timing resiliency, TSN charging and DetNet extensions; Release 19 adds QoS monitoring enhancement; Release 20 has change requests to TS 29.565 only.
- **Media focus:** the transport of SMPTE ST 2110 essence over private 5G, the alignment of the 5G and PTP time domains, and the combination with Non-Public Networks.

:::

## Specifications

The specifications in scope of Time-Sensitive Communications (TSC), grouped by the layer they define: the 3GPP service requirements and system architecture, the IEEE 802.1 Time-Sensitive Networking (TSN) standards 5G TSC is designed to interwork with, and the SMPTE standards for IP media production it carries.

## Release by release

- **Release 16**: 5G system as a TSN bridge, transparent forwarding of gPTP, DS-TT and NW-TT, TSN QoS to 5G QoS mapping. Architecture in TS 23.501, procedures in TS 23.502.
- **Release 17**: Generalised time synchronisation (multiple IEEE 802.1AS/1588 clock roles), the TSCTSF, exposure of deterministic QoS and time-sync control to Application Functions via NEF, and support for TSC independent of a full TSN bridge (deterministic QoS without requiring the wired TSN control plane).
- **Release 18**: Timing resiliency and URLLC enhancements (5TRS, TRS_URLLC): reporting of the network timing synchronisation status, interworking with a TSN network in the transport network, and scheduling adaptation from RAN feedback; charging for TSN (TSN_CH, TS 32.282); extensions of the TSC framework for DetNet (DetNet).
- **Release 19**: QoS monitoring enhancement (TEI19_QME) in the 5GC, with changes to TS 29.565; time synchronisation mechanisms in the MBS User Service architecture (TS 26.502).
- **Release 20**: change requests to TS 29.565 only. No Release 20 description (TR 21.920) exists yet; confirm against the current 3GPP work plan.

Release 16 and 17 also carried RAN work: NR_IIOT (Ethernet header compression, reference timing delivery, TSC assistance information) and NR_IIOT_URLLC_enh (propagation delay compensation, survival time). The clauses of TR 21.916 to TR 21.919 that describe each feature are on the [Release history](/standards/tsc/evolution) page.
