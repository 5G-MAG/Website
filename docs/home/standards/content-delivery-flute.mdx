<h1>FLUTE: What Each Profile Requires</h1>
</div>

Every requirement the documents place on FLUTE, grouped by feature, and for each one whether unprofiled FLUTE, MBMS download and MBS Object Distribution require it.

:::tip[At a glance]

- **Unprofiled FLUTE:** the IETF documents alone. Version 1 is RFC 3926, on ALC (RFC 3450) and LCT (RFC 3451); version 2 is RFC 6726, on ALC (RFC 5775) and LCT (RFC 5651). The FEC building block, the FEC schemes and WEBRC congestion control complete it.
- **MBMS download:** MBMS clients and servers implement RFC 3926 with the ALC and LCT features it inherits, plus the extended aspects of TS 26.346 clause 7.2, the session description of clause 7.3 and the MBMS Download Profile of annex L.4.
- **MBS Object Distribution:** the MBS Distribution Session conforms to the MBMS Download Profile, describes its objects with the Profiled FDT Schema of TS 26.346 annex L.6, and takes its session description from TS 26.346 clause 7.3 with the restrictions and extensions of TS 26.517 clause 6.2.2.
- **Releases:** the documents read are TS 26.346 V17.6.0, V18.2.0 and V19.3.0, and TS 26.517 V17.11.0, V18.7.0 and V19.3.0. What changes between them is listed at the end.

:::

## How to read the tables

- **Each row is one requirement,** gathered from the sentences of one or more documents that state it. The cell names the sections or clauses, and the strongest keyword they use: *shall* (MUST, SHALL, REQUIRED), *should* (SHOULD, RECOMMENDED), *may* (MAY, OPTIONAL). *If used* marks an FEC scheme or a congestion control scheme, whose rules apply when it is chosen.
- **Unprofiled FLUTE** lists the sections of FLUTE version 1 (v1) and version 2 (v2).
- **On an IETF row,** the 3GPP columns say whether the profile takes the requirement *as the RFC* has it, or which clause *changes*, *strengthens* or replaces it (*not used*). *Not named in the profile* marks an FEC scheme the profile does not list.
- **A 3GPP row** applies only where its clause is given; a dash means the profile does not carry it.
- **Side** says who the requirement falls on: the sender, the receiver, both, or the session description that reaches the receiver before it joins.

## Changes by release

| Release | Document | What changes |

| 17 | TS 26.346 V17.6.0 and TS 26.517 V17.11.0 | The baseline of the three profiles: the Profiled FDT Schema of annex L.6 (schemaVersion 2) and the Object Distribution Method of TS 26.517 clause 6.2 are both in Release 17 |

Segment streaming: V18.6.0 lets the DASH MPD be included in the object list; V18.7.0, like V17.11.0, requires the DASH MPD, its ancillary resources and the initialisation segments to be in the object list and retransmitted (clause 6.2.3.5). | 19 | TS 26.346 V19.3.0 | The extended FDT schema goes to schemaVersion 5 (clause 7.2.10.1) and the Profiled FDT Schema to schemaVersion 3 (clause L.6.3).
