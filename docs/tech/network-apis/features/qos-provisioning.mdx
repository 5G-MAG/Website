## Description

Developers use the "Quality of Service (QoS) Provisioning" API to request the assignment of a given QoS profile to a specific device, indefinitely. This API sets up the configuration in the network so that the requested QoS profile is applied to the specified device whenever it is connected to the network, until the provisioning is deleted (CAMARA QualityOnDemand main@471aa35 qos-provisioning.yaml info.description (indefinite assignment; 'whenever the device is connected to the network, until the assignment is revoked')).

How this compares to the other QoS APIs (all of which use a profile from the [QoS Profiles API](/tech/network-apis/features/qos-profiles)) (CAMARA QualityOnDemand main@471aa35 quality-on-demand.yaml info.description; CAMARA QualityOnDemand main@471aa35 qos-provisioning.yaml info.description; CAMARA QoSBooking main@4de93f1 qos-booking.yaml info.description):

- **QoS Provisioning (this API)**: persistent. The profile applies to the device every time it connects, until the provisioning is deleted (CAMARA QualityOnDemand main@471aa35 qos-provisioning.yaml info.description; `/qos-assignments` POST).
- [**Quality on Demand**](/tech/network-apis/features/quality-on-demand): per session. The profile applies for a requested `duration` only (CAMARA QualityOnDemand main@471aa35 quality-on-demand.yaml schemas CreateSession.duration).
- [**QoS Booking**](/tech/network-apis/features/qos-booking): reserved in advance. Capacity is booked for a future time and area (CAMARA QoSBooking main@4de93f1 qos-booking.yaml info.description; schemas serviceArea).

Information: [QoS Provisioning project page](https://camaraproject.org/qod-provisioning/) and [GitHub repository](https://github.com/camaraproject/QualityOnDemand)

The API definitions can be obtained here: [QualityOnDemand API_definitions folder](https://github.com/camaraproject/QualityOnDemand/tree/main/code/API_definitions)

The QoS Provisioning API definition (YAML) is available at: [qos-provisioning.yaml](https://github.com/camaraproject/QualityOnDemand/blob/main/code/API_definitions/qos-provisioning.yaml)

## Operations and dependencies

### QoS Provisioning API

- **POST /qos-assignments** with the request body including a `device` object and `qosProfile`, this request will assign a QoS profile to a device. The response includes an `assignmentId` (CAMARA QualityOnDemand main@471aa35 qos-provisioning.yaml `/qos-assignments` POST; schemas CreateAssignment, AssignmentInfo).
  - Dependency: Needs a `qosProfile` name, which can be retrieved from the [**QoS Profiles API**](/tech/network-apis/features/qos-profiles) or is agreed during onboarding.
- `GET /qos-assignments/{assignmentId}` - Querying for details about the QoS profile assignment (CAMARA QualityOnDemand main@471aa35 qos-provisioning.yaml `/qos-assignments/{assignmentId}` GET)
- `DELETE /qos-assignments/{assignmentId}` - Revokes the assignment of a QoS profile to a device performed by a previous assignment operation (CAMARA QualityOnDemand main@471aa35 qos-provisioning.yaml `/qos-assignments/{assignmentId}` DELETE description).
- **POST /retrieve-qos-assignment** with the request body including the `device` object, this request will return information about the QoS profile assignment for the device with an `assignmentId` (CAMARA QualityOnDemand main@471aa35 qos-provisioning.yaml `/retrieve-qos-assignment` POST; schemas RetrieveAssignmentByDevice, AssignmentInfo).

## Standardisation context

QoS Provisioning is defined in the CAMARA QualityOnDemand repository (OpenAPI 3.0.3, Commonalities-conformant). It consumes a named profile from the [QoS Profiles API](/tech/network-apis/features/qos-profiles) and, in the 3GPP northbound model, an AF session with required QoS corresponds to the NEF `AsSessionWithQoS` operation ([TS 29.522](https://www.3gpp.org/dynareport/29522.htm) V20.1.0 clause 4.4.9.2.0), in which the NEF interacts with the PCF using the `Npcf_PolicyAuthorization` service ([TS 29.514](https://www.3gpp.org/dynareport/29514.htm) V20.1.0 clause 4.1.1). The CAMARA definition does not specify how an assignment that applies until it is deleted maps to it.

The distinguishing property is persistence. Where [Quality on Demand](/tech/network-apis/features/quality-on-demand) applies a profile for a bounded session `duration`, QoS Provisioning creates an assignment (`POST /qos-assignments`) that applies the profile to the device every time it connects, until the assignment is deleted (`DELETE /qos-assignments/{assignmentId}`). `GET /qos-assignments/{assignmentId}` reads the assignment and `POST /retrieve-qos-assignment` looks it up by device. The returned `status` is `REQUESTED` (still being processed), `AVAILABLE` (assigned and active) or `UNAVAILABLE` (processed but not active).

### Comparison within the QoS family

| API                                                           | Duration                  | Bound to                       | Typical media use                                               |
| ------------------------------------------------------------- | ------------------------- | ------------------------------ | --------------------------------------------------------------- |
| QoS Provisioning (this API)                                   | Persistent, until deleted | A specific device              | A fixed contribution device that should always get its profile. (CAMARA QualityOnDemand main@471aa35 qos-provisioning.yaml info.description; `/qos-assignments` POST) |
| [Quality on Demand](/tech/network-apis/features/quality-on-demand)               | One session (`duration`)  | A device flow                  | A boost for the length of a live feed. (CAMARA QualityOnDemand main@471aa35 quality-on-demand.yaml schemas CreateSession.duration; info.description) |
| [QoS Booking](/tech/network-apis/features/qos-booking)                           | A future window           | A specific device                 | Capacity secured ahead of a scheduled event. (CAMARA QoSBooking main@4de93f1 qos-booking.yaml info.description; `/device-qos-bookings` POST) |
| [QoS Booking and Assignment](/tech/network-apis/features/qos-booking-assignment) | A future window           | A device count, assigned later | An event where devices are only known on the day. (CAMARA QoSBooking main@4de93f1 qos-booking-and-assignment.yaml info.description; schemas bookingDeviceCount; info.description) |

A practical limitation for media, recorded in the Self-Assessment below, is that the assignment cannot be re-pointed to a different device: replacing a device means deleting the assignment and creating a new one, with no guarantee the new assignment succeeds. There is also no service-area dimension (CAMARA QualityOnDemand main@471aa35 qos-provisioning.yaml paths; schemas CreateAssignment; `/qos-assignments` POST description (201 may carry UNAVAILABLE).

### Step 0: Pre-conditions

- The API invoker needs to have signed up with the API provider (CAMARA QualityOnDemand main@471aa35 qos-provisioning.yaml info.description).
- qosProfiles have already been defined and made available by the network operator (CAMARA QoSProfiles main@8ce8f4d qos-profiles.yaml info.description; CAMARA QualityOnDemand main@471aa35 qos-provisioning.yaml info.description).
- Names of such qosProfiles have been disclosed to the user so they can be used when invoking APIs (CAMARA QualityOnDemand main@471aa35 qos-provisioning.yaml info.description).

### Step 1: Check details of an existing QoS Profile (when not cached)

- `GET /qos-profiles/{name}` to obtain the parameters of the QoS Profile (CAMARA QoSProfiles main@8ce8f4d qos-profiles.yaml `/qos-profiles/{name}` GET)

### Step 2: Attach a device to the QoS Profile

- **POST /qos-assignments** passing the `device` object and the name of the `qosProfile` (CAMARA QualityOnDemand main@471aa35 qos-provisioning.yaml `/qos-assignments` POST; schemas CreateAssignment)
- The received "assignmentId" could be used to query details or revoke the assignment (CAMARA QualityOnDemand main@471aa35 qos-provisioning.yaml parameters assignmentId; schemas AssignmentInfo.assignmentId; `/qos-assignments/{assignmentId}` GET, DELETE)
- This QoS profile will be assigned to the device anytime it is connected to the network (CAMARA QualityOnDemand main@471aa35 qos-provisioning.yaml info.description).

## 5G-MAG's Self-Assessment

This section records 5G-MAG's practical reading of the API and the open points it raises for media use.

This API would allow attaching a QoS Profile to a device any time it is connected to the network (CAMARA QualityOnDemand main@471aa35 qos-provisioning.yaml info.description).
There is an issue as it is not possible to assign a different device to the existing QoS assignment. If a device would need to be replaced during operation, the existing QoS assignment would have to be deleted and a new assignment created. While doing so there is no guarantee that such new assignment is possible.

Potential improvements:

- Ability to update the device to which the QoS Profile applies.
- There is no information about the location or service area (CAMARA QualityOnDemand main@471aa35 qos-provisioning.yaml schemas CreateAssignment, AssignmentInfo).
- Understanding opportunities in terms of duration and location/area would be useful as the user may be able to move and find a better coverage spot rather than being denied the establishment of QoS at the time and location in which it is requested.

## Quality-on-Demand (QoD) Provisioning API Usage

### Assigning a QoS profile to a device

With **POST /qos-assignments**, passing the `qosProfile` name and, with a two-legged access token, the `device` object; an optional `sink` receives notifications. The request below is built from the `CreateAssignment` schema (CAMARA QualityOnDemand main@471aa35 qos-provisioning.yaml `/qos-assignments` POST; schemas CreateAssignment, BaseAssignmentInfo):

```json
{
  "device": {
    "phoneNumber": "+123456789"
  },
  "qosProfile": "QOS_L",
  "sink": "https://application-server.com/callback"
}
```

Type of response: the assignment with its `assignmentId` and the initial `status` `REQUESTED`. The example is the CAMARA example `ASSIGNMENT_CREATION_EXAMPLE_WITH_DEVICE_RESPONSE`; if more than one device identifier was sent, only one is returned (CAMARA QualityOnDemand main@471aa35 qos-provisioning.yaml examples ASSIGNMENT_CREATION_EXAMPLE_WITH_DEVICE_RESPONSE; schemas Status):

```json
{
  "device": {
    "phoneNumber": "+123456789"
  },
  "qosProfile": "QOS_L",
  "sink": "https://application-server.com/callback",
  "assignmentId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "status": "REQUESTED"
}
```

### Obtaining the QoS assignment for a device

With **POST /retrieve-qos-assignment**, and device object. The request identifies the device whose assignment is queried (CAMARA QualityOnDemand main@471aa35 qos-provisioning.yaml `/retrieve-qos-assignment` POST; schemas RetrieveAssignmentByDevice):

```json
{
  "device": {
    "phoneNumber": "+123456789",
    "ipv4Address": {
      "publicAddress": "203.0.113.0",
      "publicPort": 59765
    },
    "ipv6Address": "2001:db8:85a3:8d3:1319:8a2e:370:7344"
  }
}
```

Type of response: the assignment details, including the assigned `qosProfile`, the `assignmentId` (used to query or revoke it) and its current `status` (CAMARA QualityOnDemand main@471aa35 qos-provisioning.yaml schemas AssignmentInfo):

```json
{
  "device": {
    "phoneNumber": "+123456789"
  },
  "qosProfile": "QOS_L",
  "sink": "https://application-server.com/callback",
  "sinkCredential": {
    "credentialType": "ACCESSTOKEN",
    "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c",
    "accessTokenExpiresUtc": "2024-12-01T12:00:00Z",
    "accessTokenType": "bearer"
  },
```

## Event notifications

When a `sink` is given, the API provider notifies status changes of the assignment as CloudEvents. The event type is `org.camaraproject.qos-provisioning.v0.status-changed`, and the `data` carries the `assignmentId`, the `status` (`AVAILABLE` or `UNAVAILABLE`) and optionally a `statusInfo` (CAMARA QualityOnDemand main@471aa35 qos-provisioning.yaml QosProvisioningEventType; EventStatusChanged; StatusChanged). The CAMARA example for an assignment that became unavailable is below (examples ASSIGNMENT_STATUS_CHANGED_EXAMPLE):

```json
{
  "id": "83a0d986-0866-4f38-b8c0-fc65bfcda452",
  "source": "https://api.example.com/qos-provisioning/v0.4/qos-assignments/123e4567-e89b-12d3-a456-426614174000",
  "specversion": "1.0",
  "type": "org.camaraproject.qos-provisioning.v0.status-changed",
  "time": "2021-12-12T00:00:00Z",
  "data": {
    "assignmentId": "123e4567-e89b-12d3-a456-426614174000",
    "status": "UNAVAILABLE",
    "statusInfo": "NETWORK_TERMINATED"
  }
}
```
