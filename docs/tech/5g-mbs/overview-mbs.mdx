<h1>5G Multicast Broadcast Services (MBS)</h1>
</div>
</div>

:::tip[At a glance]

- **Two parts:** MBS User Services, a service layer made of the MBSF and the MBSTF; and MBS in the 5G System and NG-RAN, with the MB-SMF and MB-UPF in the core and multicast and broadcast radio bearers in NR.
- **Two communication services:** broadcast, for all UEs in a geographical area, and multicast, for a dedicated set of UEs.
- **Delivery:** between the 5G Core and NG-RAN, 5GC Shared or 5GC Individual MBS traffic delivery; over the radio, point-to-multipoint (PTM) or point-to-point (PTP).
- **Optional service layer:** the MBSF and MBSTF are optional in the 5G System. Without them, MBS transports the data without modifying it.

:::

## MBS User Services

MBS User Services let high-level applications use the low-level features of the MBS System. An MBS User Service is provided by two functions working together:

- **MBSF (Multicast/Broadcast Service Function):** the control plane function. It receives provisioning from the MBS Application Provider and controls the MBSTF.
- **MBSTF (Multicast/Broadcast Service Transport Function):** the user plane function. It ingests content from the MBS Application Provider and sends MBS data packets towards the 5G Core.

The **MBS Application Provider** plays the role of the Application Function and Application Server (AF/AS). On the device, the **MBS Client** is a function of the User Equipment (UE). An **MBS-Aware Application** uses the MBS Client through its APIs, which let it activate or deactivate reception of MBS User Services. TS 26.502 does not define the MBS-Aware Application itself.

The service layer delivers data with two **distribution methods**, the Object Distribution Method and the Packet Distribution Method. Either can use a multicast or a broadcast MBS Session. They provide security and key distribution, reliability control by means of Forward Erasure Correction (FEC), and the associated delivery procedures.

An **MBS User Service Announcement** gives the MBS Client the service access information it needs to discover an MBS User Service and activate its reception. TS 26.517 defines the protocols and formats used by MBS User Services. Reporting by the MBS Client to the MBSF is for further study.

## MBS

MBS is a point-to-multipoint service: data is transmitted from a single source to multiple recipients, either to all users in a broadcast service area or to the users in a multicast group. TS 23.247 states what its architecture provides:

- efficient usage of radio access and core network resources, with an emphasis on radio interface efficiency;
- efficient transport for a variety of multicast and broadcast services.

The architecture follows the 5G System principles of TS 23.501. It distributes MBS data from the 5G System ingress to the NG-RAN nodes and then to the UE. TS 38.300 states that the NR system enables resource efficient delivery of multicast and broadcast services.

Two communication services are defined:

- **Broadcast communication service:** the same content is provided at the same time to all UEs in a geographical area. The content provider and the network may not be aware whether the UEs are actually receiving it. A UE can receive it in RRC_IDLE, RRC_INACTIVE and RRC_CONNECTED.
- **Multicast communication service:** the same content is provided at the same time to a dedicated set of UEs. The content provider and the network can be aware whether the UEs are actually receiving it. A UE can receive it in RRC_CONNECTED, with PTP and/or PTM delivery, and in RRC_INACTIVE, with PTM delivery.

Two functions are added to the 5G Core: the **MB-SMF**, which manages MBS sessions and allocates TMGIs, and the **MB-UPF**, which handles the multicast and broadcast data. Existing functions are extended, among them the AMF, SMF, UPF, PCF, NEF, NRF and UDM, and NG-RAN and the UE. NG-RAN is the decision point for switching between PTP and PTM. MBS for roaming is not supported in Release 18.

## How the two parts fit

In the 5G System, the MBSF and the MBSTF are optional. TS 23.247 annex A defines three configuration options:

| Option | Service layer | Control plane entry point for the AF | User plane entry point for the AF |
| --- | --- | --- | --- |
| **1** | No MBSF. Transport Only Mode: MBS transports the data without modifying it | NEF at N33 (an AF in the trusted domain may use the core interfaces directly) | MB-UPF at N6mb |
| **2** | MBSF, reached through the NEF | NEF at N33 | MBSTF at Nmb8 (or MB2-U, xMB-U) |
| **3** | MBSF, reached directly | MBSF at Nmb10 (or MB2-C, xMB-C) | MBSTF at Nmb8 (or MB2-U, xMB-U) |

For Service Mode, in which the service layer may modify the data, the MBSF is used: option 2 or option 3. MBS User Services support options 2 and 3, and TS 26.502 does not address deployments without an MBSTF.

When the service layer is used, the MBSF invokes MBS Session operations on the MB-SMF at reference point Nmb1, and the MBSTF sends MBS data packets to the MB-UPF at Nmb9. In every option, the MB-UPF receives only one copy of the MBS data packets, from the AF or from the MBSTF.
