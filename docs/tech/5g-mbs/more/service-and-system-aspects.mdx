<h1>MBS - Service &amp; System</h1>

:::tip[At a glance]

- **Services:** the multicast communication service goes to a dedicated set of UEs; the broadcast communication service goes to all UEs in a geographical area.
- **Sessions:** a multicast MBS session delivers the multicast communication service, a broadcast MBS session the broadcast communication service.
- **Delivery:** the 5GC shared MBS traffic delivery method is required for broadcast and may be used for multicast; the 5GC individual MBS traffic delivery method is used for multicast only.

:::

## MBS communication services (TS 23.247)

TS 23.247 defines two new logical communication services (TS 23.247 V20.0.0 clause 3.1):

- **Multicast communication service**: A 5GS communication service in which the same service and the same specific content data are provided simultaneously to a dedicated set of UEs i.e. not all UEs in the coverage of the MBS service area are authorised to receive the data (TS 23.247 V20.0.0 clause 3.1).
- **Broadcast communication service**: A 5GS communication service in which the same service and the same specific content data are provided simultaneously to all UEs in a geographical area i.e. all UEs in the broadcast coverage area are authorised to receive the data (TS 23.247 V20.0.0 clause 3.1). The content provider and network may not be aware whether authorised UEs are actually receiving the data being delivered (TS 23.247 V20.0.0 clause 3.1, note 1).

## MBS sessions (TS 23.247)

TS 23.247 defines MBS sessions as follows (TS 23.247 V20.0.0 clause 3.1):

- **MBS session**: A multicast or broadcast session (TS 23.247 V20.0.0 clause 3.1).
- **Broadcast MBS session**: An MBS session to deliver a broadcast communication service. A broadcast MBS session is characterised by the content to send and the geographical area over which to distribute it (TS 23.247 V20.0.0 clause 3.1).
- **Multicast MBS session**: An MBS session to deliver a multicast communication service. A multicast MBS session is characterised by the content to send, the list of UEs that may receive the service and optionally by a geographical area over which to distribute it (TS 23.247 V20.0.0 clause 3.1).

Broadcast and multicast MBS sessions are time-bound (TS 23.247 V20.0.0 clause 4.2.1; TS 23.247 V20.0.0 clause 4.2.2). Their life-cycles are specified in clauses 4.2 and 4.3 of TS 23.247 (TS 23.247 V20.0.0 clause 4.2; TS 23.247 V20.0.0 clause 4.3).

The geographical areas for which the multicast and broadcast MBS sessions are available is determined by the coverage area of the sites/sectors from which the broadcast service is transmitted (TS 23.247 V20.0.0 clause 3.1, note 2). Refer to TS 23.247 clause 3.1 and TS 38.300 for more detail.

## MBS traffic delivery methods (TS 23.247)

Multicast–broadcast Protocol Data Units, referred to as MBS packets, are supplied to the MB-UPF by the AF or the MBSTF and from there conveyed across the 5G Core Network (CN) using one of two different MBS traffic delivery methods (TS 23.247 V20.0.0 clause 6.7; TS 23.247 V20.0.0 clause 4.1):

- **5GC shared MBS traffic delivery method**: 5G CN receives a single copy of MBS data packets and delivers a single copy of those MBS data packets to each relevant RAN node (TS 23.247 V20.0.0 clause 3.1; TS 23.247 V20.0.0 clause 4.1).
  - This method must be applied for broadcast MBS sessions (TS 23.247 V20.0.0 clause 4.1).
  - This method may be applied to multicast MBS sessions (TS 23.247 V20.0.0 clause 4.1).
  - MBS packet is forwarded by the MB-UPF directly to the relevant NG-RAN nodes at their N3mb reference point via a GTP-U tunnel (a common tunnel with multicast transport, a separate tunnel per NG-RAN node with unicast transport) (TS 23.247 V20.0.0 clause 6.7).
  - Each MBS Session establishes its own separate set of shared tunnels as required; tunnels are not shared across different MBS sessions (TS 23.247 V20.0.0 clause 6.7).

- **5GC individual MBS traffic delivery method**: the 5G CN receives a single copy of MBS data packets and delivers separate copies of those MBS data packets to individual UEs via per-UE Protocol Data Unit (PDU) sessions. For this traffic delivery method each UE associated with a multicast session requires its own, dedicated PDU session (TS 23.247 V20.0.0 clause 3.1; TS 23.247 V20.0.0 clause 4.1).
  - This method is only applied to multicast MBS sessions (TS 23.247 V20.0.0 clause 4.1).
  - Because an MNO network may contain an arbitrary mix of MBS-capable and MBS-incapable gNodeBs, the same MBS packet (originating from a multicast MBS session) may be conveyed to MBS-capable gNodeBs using the shared MBS traffic delivery method, and to MBS-incapable gNodeBs via one or more PDU Sessions using the individual MBS traffic delivery method (TS 23.247 V20.0.0 clause 4.1; TS 23.247 V20.0.0 clause 3.1, definition of MB-SMF service area).
  - MBS packets are forwarded by the MB-UPF to the UPF at reference point N19mb where they are delivered to the NG-RAN in a conventional PDU Session in a GTP tunnel at existing reference point N3, and thence to the target UE at reference point Uu. In this scenario, a separate PDU Session is required for each subscribed UE and the UPF is responsible for performing the necessary packet replication at this fan-out point (TS 23.247 V20.0.0 clause 6.7).
