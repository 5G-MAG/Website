<h1>5G Core Service Consumers</h1>
</div>
</div>

:::tip[At a glance]

- **What it is:** the 5G Core Service Consumers libraries, which package the consumer side of 5G Core services so 5G-MAG components can reuse it.
- **Why it matters:** Components such as an Application Function can then call 5G Core Network Functions without each rebuilding the client side.
- **In this section:** This page lists the services consumed from the PCF, BSF, MB-SMF and NRF, and what each library does.

:::

<JumpMenu items={[["The services consumed", "the-services-consumed"], ["What each library consumes", "what-each-library-consumes"], ["What later releases changed", "what-later-releases-changed"]]} />

The 5G Core is made of Network Functions, each offering services through service-based interfaces. A component that needs one of those services acts as the **NF service consumer** of it. The 5G Core Service Consumers libraries package that consumer side so that different 5G-MAG components can reuse it, for example an Application Function calling the PCF, or the MBS Function calling the MB-SMF. Only the Network Functions that 5G Media Streaming and 5G MBS use are covered.

## The services consumed

| Network Function | Service | Specification | Service operations |
| --- | --- | --- | --- |
| PCF | `Npcf_PolicyAuthorization` | TS 29.514 V20.1.0 clause 4.2 | Create, Update, Delete, Notify, Subscribe and Unsubscribe (clauses 4.2.2 to 4.2.7) |
| BSF | `Nbsf_Management` | TS 29.521 V20.1.0 clause 4.2 | Register, Deregister, Discovery, Update, Subscribe, Unsubscribe and Notify (clauses 4.2.2 to 4.2.8) |
| MB-SMF | `Nmbsmf_TMGI` | TS 29.532 V20.0.0 clause 5.2.2 | TMGI Allocate and TMGI Deallocate (clauses 5.2.2.2 and 5.2.2.3) |
| MB-SMF | `Nmbsmf_MBSSession` | TS 29.532 V20.0.0 clause 5.3.2 | Create, Update, Release, ContextUpdate, StatusSubscribe, StatusUnsubscribe, StatusNotify, ContextStatusSubscribe, ContextStatusUnSubscribe and ContextStatusNotify (clauses 5.3.2.2 to 5.3.2.11) |
| NRF | `Nnrf_NFDiscovery` | TS 29.510 V20.1.0 clause 5.3.2 | NFDiscover, SCPDomainRoutingInfoGet, SCPDomainRoutingInfoSubscribe, SCPDomainRoutingInfoNotify and SCPDomainRoutingInfoUnSubscribe (clauses 5.3.2.2 to 5.3.2.6) |

## What each library consumes

- **PCF library** (`libscpcf`): an Application Function asks the PCF to change the network routing policy of the traffic flows of a UE's PDU session by creating an application session context, with `Npcf_PolicyAuthorization` at reference point N5.
- **BSF library** (`libscbsf`): finds which PCF manages the PDU session of a UE, identified by its IP address, with `Nbsf_Management`; the BSF itself is found by asking the NRF.
- **MB-SMF library** (`libscmbsmf`): allocates and deallocates TMGIs with `Nmbsmf_TMGI`, and creates, modifies and destroys MBS Sessions and subscribes to their events with `Nmbsmf_MBSSession`, at reference point Nmb1.

These three descriptions are those of the project's own README; the specifications above define the services.

## What later releases changed

Each service was first specified in the release shown on the [Standards page](/standards/5g-core); the Category B change requests in the specifications record later additions. For the operations used here:

- **`Npcf_PolicyAuthorization`:** Release 16 added QoS monitoring for service data flows (TS 29.514 V20.1.0 change history, CR 0142); Release 18 added multi-modal, PDU set and L4S support for XR and media services (TR 21.918 clause 14.8; CRs 0473, 0488, 0508, 0528); Release 19 added the MPS for Messaging indication on N5 (TR 21.919 clause 20.6; CR 0682).
- **`Nbsf_Management`:** Release 16 allowed several UE addresses in one binding and binding update (TS 29.521 V20.1.0 change history, CRs 0037, 0038); Release 17 added subscription to PCF registration and discovery of a PCF for a UE (CRs 0113, 0130) and the PCF for an MBS Session binding (CRs 0158 to 0161), with the MBSF named as a consumer of discovery (CR 0164).
- **`Nmbsmf_TMGI` and `Nmbsmf_MBSSession`:** TS 29.532 was approved at version 17.0.0; Release 18 added the Associated Session ID in Create, RedCap UE information and MOCN support (TS 29.532 V20.0.0 change history, CRs 0054, 0085, 0086).
- **`Nnrf_NFDiscovery`:** Release 17 added SCP domain routing information (TS 29.510 V20.1.0 change history, CR 0417) and MB-SMF registration and discovery (CRs 0552, 0577, 0636); Release 18 added shared data (TR 21.918 clause 10.9; CR 0905); Release 19 added selective parameter omission in responses (TR 21.919 clause 22.3).

- **Release 20 (work plan of 28 September 2026):** the work plan lists TS 29.510 under AmbientIoT_Ph2-CT, TEI20_NEPS-CT, Sensing-CT, EnergySys_Ph2-CT and AIML_CN_Ph2-CT, and TS 29.514 under EnergySys_Ph2-CT, TEI20_SCONE-CT and SMPC20-CT. The change histories record, for example, energy-aware NF discovery and selection (TS 29.510 V20.1.0, CR 1310), and energy indicator provisioning and SCONE functionality (TS 29.514 V20.0.0, CRs 0843 and 0844). The change histories do not name the work item of each change request. The full list is on the [Standards page](/standards/5g-core).
