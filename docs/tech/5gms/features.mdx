TS 26.501 defines a set of high-level features for supporting enhanced media streaming in the 5G System. Each applies to downlink, uplink or both.

:::tip[At a glance]

- **13 features:** eight from Release 16, three added in Release 17, two in Release 18, none in Release 19.
- **Directions:** content hosting, consumption reporting, QoE metrics reporting and delivery via eMBMS and MBS are downlink; content publishing and remote control are uplink; the others apply to both.
- **APIs:** up to Release 17, TS 26.512 specifies each API with its own OpenAPI file. From Release 18 they are TS 26.510 services that TS 26.512 refers to. Each feature shows both, folded.
- **Added in Release 19** in the API tables: content redistribution at M10 and metrics reporting at M3d. TS 26.512 V19.3.0 also adds in-band CMCD reporting at M4d (clause 10.5), which its table 4.2-1 does not list.

:::

## Feature by feature

For each feature: what it does, where TS 26.501 defines it, and the reference points, APIs and OpenAPI files that implement it. The APIs are in two tables, because Release 18 moved them:

- **Up to Release 17:** TS 26.512 specifies each API itself, with its own OpenAPI file (`TS26512_M1_…`, `TS26512_M5_…`). The rows come from TS 26.512 V17.10.0 tables 4.2-1 (downlink) and 5.2-1 (uplink).
- **From Release 18:** the provisioning and media session handling APIs are specified in TS 26.510, and TS 26.512 refers to them. The rows come from TS 26.512 V19.3.0 tables 4.2-1 and 5.2-1; the TS 26.510 clause is the one TS 26.512 points to, with its procedure clause in brackets. TS 26.510 clauses 8, 9 and 11 are numbered the same in V18.5.0 and V19.2.0. "Added in Release 19" marks a row that TS 26.512 V18.7.0 does not list.

The OpenAPI file is the one whose title matches the API, in that version's archive. From Release 18, TS 26.512 also ships 5GMS wrapper files (`TS26512_Maf_Provisioning.yaml`, `TS26512_Maf_SessionHandling.yaml`) and states that where any discrepancy exists, the version on 3GPP Forge is definitive.

### Content hosting

**Downlink** · added in Release 16 · defined in TS 26.501 clause 4.0.2 · procedures in clause 5.4

Provides a service equivalent to a Content Delivery Network (CDN), inside or outside the trusted data network. Content is ingested pull-based (retrieved from a media origin at the Application Provider) or push-based (published by the Application Provider), may be cached across one or more service locations, may be manipulated according to Content Preparation Templates, and is then retrieved by the 5GMSd Client. A provisioned Server Certificate may secure the content served.

### Content preparation

**Downlink and uplink** · added in Release 16 · defined in TS 26.501 clause 4.0.4

Lets the Application Provider specify how network-side components manipulate content, according to provisioned Content Preparation Templates. It may include encoding, transcoding, packaging, encryption and protecting content with DRM. It is provisioned as part of content hosting (downlink) or content publishing (uplink). From Release 18, its APIs are the Content Preparation Templates rows of those two features. Up to Release 17, TS 26.512 lists the downlink API under content hosting and the uplink API as a feature of its own, below.

### Network assistance

**Downlink and uplink** · added in Release 16 · defined in TS 26.501 clause 4.0.5 · procedures in clause 5.9 (d); 6.5, 6.7 (u) in table 4.0.1-1, or 6.1, 6.5, 6.7 (u) in clause 4.0.5

Lets the 5GMS Client interrogate or manipulate the network Quality of Service (QoS) of an ongoing session. It is not explicitly provisioned: whether it is available depends on system pre-configuration and policy. Two mechanisms: AF-based, through the PCF, and ANBR-based, between the UE modem and the RAN. Two sub-features: bit rate recommendation (throughput estimation), and delivery boost, a speculative request for a temporary boost to the session bit rate.

### Dynamic policies

**Downlink and uplink** · added in Release 16 · defined in TS 26.501 clause 4.0.6 · procedures in clause 5.8, 5.7.6 (d); 6.9 (u)

Lets the 5GMS Client manipulate the network traffic handling policies of an ongoing session. The Application Provider provisions Policy Templates within a Provisioning Session. Each Policy Template carries an External reference and the Network QoS parameters of one Service Operation Point (for example SD, HD or UHD), and may apply to one or more Data Networks or Network Slices. Media Entry Point documents refer to the same Service Operation Points in their Service Descriptions. Outside the trusted data network, the PCF is reached through the NEF.

### QoE metrics reporting

**Downlink (see note)** · added in Release 16 · defined in TS 26.501 clause 4.0.9 · procedures in clause 5.5

Two mechanisms: RAN-based, with reports sent to the OAM via the RAN, and AF-based, with reports sent to network-side components of the 5GMS System. Data in AF-based reports may be exposed as events. TS 26.501 clause 4.0.9 limits the feature to downlink in the current release, while TS 26.512 table 5.2-1 lists uplink metrics reporting APIs and TS 26.501 clause 4.3.1 includes QoE metrics reporting at M5u; both are shown below. For uplink, TS 26.512 clause 7.8.1 adds that no standardised metrics schemes are defined for uplink media streaming.

### Service URL handling

**Downlink and uplink** · added in Release 18 · defined in TS 26.501 clause 4.0.13 · procedures in clause 9, 5.10.7 (d); 9 (u)

A 3GPP Service URL launches UE functions when it is executed. A 5GMS service can be announced in a third-party application, a web page, a messaging service or shared through social messages. When a service is launched with a 3GPP Service URL for 5GMS, a 5GMS Client function for media session handling is expected to launch alongside. Defined in TS 26.501 clause 4.10; the generic 3GPP Service URL is in TS 26.510 clause 6 and the 5GMS one in TS 26.512 clause 12.4.
