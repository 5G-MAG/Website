For MPEG#156, held in Hangzhou in October 2026, 5G-MAG provided MPEG Systems (ISO/IEC JTC 1/SC 29/WG 3) with an update on its two immersive-media projects: [XR Media & 3D Scenes](/reference-tools/xr) and [Conversational Avatar Communication](/reference-tools/avatar). The contribution, m78825 "[SD] XR and MPEG-I in 5G-MAG Reference Tools", is listed on the [liaison statements page](/ls).

{/* truncate */}

The two projects turn MPEG-I Scene Description (ISO/IEC 23090-14) and the Avatar Representation Format (ISO/IEC 23090-39) into running, open-source software, and connect them to the 3GPP service specifications.

## XR Media & 3D Scenes

The [XR Media & 3D Scenes](/reference-tools/xr) project composes, positions and synchronises dynamic 3D visual and audio objects in time. Its reference tools cover authoring, reference content, Media Access Function (MAF) pipelines, parsing of the MPEG-I glTF extensions and playback in Unity3D on Windows and Android. The standards basis is ISO/IEC 23090-14, second edition, ISO/IEC 12113 (glTF 2.0) and 3GPP TS 26.119.

What is new in the update:

- **An XR Scene Player for Android.** The smartphone application is in open pull request [#126](https://github.com/5G-MAG/rt-xr-unity-player/pull/126) of the XR Unity Player. Its AR example anchors a video scene to the floor of the room the camera sees, and the app provides media controls, scene details and a content library.
- **A scene validator.** Open pull request [#45](https://github.com/5G-MAG/rt-xr-content/pull/45) of rt-xr-content checks scenes against the MPEG JSON schemas and rules derived from the specification. Each finding gives its severity, the applicable clause, the rule that was checked and the location in the scene.
- **Reference scenes.** rt-xr-content includes scenes that combine video textures and spatial audio, scenes for AR anchoring in the real world, and scenes in which user input triggers an animation.
- **Timed metadata and maintenance.** Open pull requests in rt-xr-maf-native and rt-xr-gITFast address decoding of timed metadata tracks and fixes for Scene Description extensions and interactivity.

## Conversational Avatar Communication

The [Conversational Avatar Communication](/reference-tools/avatar) project animates avatars from user to user in real time. The 5G-MAG implementation demonstrates a one-to-one call using MPEG ARF and the receiver-centric animation mode of 3GPP TS 26.264, in which the receiving device animates and renders the sender's avatar. A two-phone demonstration was shown at MPEG in Geneva on 14 July 2026 and at IBC on 13 September 2026.

Releases of 16 October 2026: rt-avatar-call v0.10.154 (command-line build tooling and updated default camera framing), rt-avatar-content v0.10.154, and rt-3gpp-swap v0.9, which closes the identified conformance gaps against clause 13.2.4 of 3GPP TS 26.113. Pre-release v0.10.155-b2 adds initial support for avatars based on Gaussian splatting. Android XR animation generation and fetching of avatars from the Base Avatar Repository are in development, and body-animation support and a call-flow user interface are planned.

Read more on the [technology page](/tech/avatar), the [Reference Tools](/reference-tools/avatar) and the [specifications](/standards/avatar).

## What it means for MPEG

The update gives MPEG implementation evidence rather than demonstrations alone:

- the Scene Description implementation cross-checks the Presentation Engine and MAF separation, the MAF and Buffer APIs, the `MPEG_*` glTF extensions and the carriage of timed media;
- the validator is a route from normative clauses and JSON schemas to repeatable checks, and can show specification ambiguities or implementation gaps;
- the reference scenes are candidate test assets for reference software, conformance work, demonstrations and interoperability;
- the avatar project exercises ARF base avatars and animation streams inside an end-to-end 3GPP conversational service flow.

5G-MAG proposed that MPEG take the contribution into account, evaluate the reference scenes and the validator as inputs to reference software and conformance work (including ISO/IEC 23090-24 where appropriate), use implementation findings as feedback for the maintenance of Scene Description and ARF, and encourage MPEG-I experts and implementers to contribute code, test assets, validation rules and interoperability feedback through the 5G-MAG reference-tool projects.

More on how 5G-MAG feeds implementation experience back to standards bodies is on the [Standardisation](/standards) pages.
